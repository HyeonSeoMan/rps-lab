# Verification: 가위바위보 (001-rps-game) 수동·스모크 검증 기록

**일시**: 2026-11-05
**대상 빌드**: `npm run build` 후 `next start` (프로덕션 빌드, Next.js 16.4.5)
**환경**: macOS (Darwin 25.6.0), Google Chrome 156.0.8078.80 **headless**, Chrome DevTools Protocol(CDP)로 구동. 폭은 `Emulation.setDeviceMetricsOverride`로 에뮬레이션(실기기 아님).
**방법 주의**: 아래 결과는 사람이 직접 조작한 것이 아니라 CDP 스크립트로 측정한 것이다(스크립트는 저장소 밖 임시 폴더에만 있으며 저장소에 추가하지 않았다). 사람의 시각 평가가 필요한 항목, 실기기, 다른 브라우저는 **미수행**으로 표시했다.

## T025 수동 검증 (quickstart 2번 표)

| 항목 | 환경 / 폭 | 결과 | 비고 |
|---|---|---|---|
| AC-010 320px 가로 스크롤 없음 | Chrome 156 headless, 320px | **통과** | 3라운드 진행 후 `scrollWidth(320) == clientWidth`, 뷰포트 밖으로 나가는 요소 0개. 화면 안 결과 문장·전적·버튼 모두 표시 |
| AC-011 1280px 이상 겹침·깨짐 없음 | Chrome 156 headless, 1280px | **통과** | 가로 스크롤 없음. 스크린샷으로 대결 영역(나 / 결과 / 컴퓨터)·선택 버튼·전적·초기화 버튼이 겹침 없이 중앙 정렬임을 육안 확인 |
| AC-012 버튼 렌더 크기 ≥ 44×44 | 320px, 1280px | **통과** | 320px: 선택 94.7×92, 초기화 108.2×44. 1280px: 선택 282.7×105, 초기화 108.2×44 (CSS px, `getBoundingClientRect`) |
| AC-015 `{"wins":999,"losses":1000,"draws":1234}` 후 320px | Chrome 156 headless, 320px | **통과** | 전적 999 / 1000 / 1234 표시, 가로 스크롤 없음, 스크린샷으로 숫자 잘림·줄바꿈 없음 확인 |
| AC-016 서버 요청 없음 | Chrome 156 headless, 375px | **통과** | 페이지 로드 완료 후 6라운드 + 초기화 동안 `Network.requestWillBeSent` 0건 (초기 문서·정적 자원 로드는 제외). 자동 보조 테스트(`fetch` 스파이)도 통과 |
| SC-001 처음 보는 사람이 10초 내 첫 라운드 | — | **미수행(사람 평가 필요)** | 사람 대상 항목이라 자동화할 수 없다. 참고 계측: 로드 후 클릭 → 결과 문장 갱신까지 52ms |
| SC-004 선택 직후 1초 내 결과 | Chrome 156 headless | **통과** | 10회 클릭 중 결과 문장이 바뀐 6회의 클릭→갱신 시간 0.6~1.1ms(최대 1.1ms). 나머지 4회는 직전과 같은 결과 문장이라 변화 감지 대상이 아니었다 |
| 깜빡임 (저장값 상태 반복 새로고침) | Chrome 156 headless, 정상 5회 + 네트워크 지연 400ms·대역폭 50KB/s·CPU 6배 스로틀 5회 | **통과** | 저장값 7/5/3. 프레임마다 전적 표시를 기록한 결과 10회 모두 `(없음) → 7,5,3`만 관찰되고 `0,0,0`이 나타난 적 없음. 값이 나타나기 전에는 전적 영역이 비어 있음 |
| 실기기 모바일 1종 탭 1회 = 1라운드 | — | **미수행(실기기 필요)** | 실기기가 없어 수행하지 못했다. 사용자 확인 필요. 보조: Chrome 터치 에뮬레이션(375px)으로 touchStart/touchEnd 1회 → 합계 0 → 1 |

### 수행하지 못한 항목 (사용자 확인 필요)

1. **SC-001**: 처음 보는 사람이 안내 없이 10초 내 첫 라운드를 끝내는지(사람 평가).
2. **실기기 모바일 1종**: 탭 1회 = 1라운드, 실제 터치 반응과 레이아웃.
3. **다른 브라우저(Safari, Firefox)**와 실제 스크린리더: 이번 검증 범위 밖이며 Plan P-5의 "모바일 1종 + 데스크톱 1종" 기록 기준 중 모바일이 비어 있다.

### 참고 관찰

- 320px/1280px 측정에서 `scrollWidth > clientWidth`로 잡힌 요소는 시각적으로 숨긴 결과 문장(`role="status"`, sr-only 1px 영역) 1개뿐이며, 화면에 보이는 요소는 없었다.

## T026 기능 흐름 스모크 (quickstart 3번, 6단계)

환경: 위와 동일(1280px). 매 단계 localStorage를 초기화한 상태에서 시작.

| 단계 | 기대 | 결과 |
|---|---|---|
| 1. 첫 접속 | 0/0/0, 안내 문구 | **통과** — 전적 0/0/0, 상태 문장 "가위, 바위, 보 중 하나를 선택하세요" |
| 2. "바위" 클릭 | 양쪽 선택·결과 표시, 합계 1 | **통과** — "나: 바위 · 컴퓨터: 가위 — 승리!", 대결 영역 `나 ✊ 바위 VS 승리! 컴퓨터 ✌️ 가위`, 합계 1 |
| 3. 빠르게 3회 연속 클릭 | 합계 정확히 4 | **통과** — 합계 4 |
| 4. 새로고침 | 전적 유지(잘못된 0/0/0 없음), 결과 영역은 초기 안내 | **통과** — 2/1/1(합계 4) 유지, 상태 문장은 초기 안내, 전적 표시 이력 `(없음) → 2,1,1` |
| 5. "전적 초기화" | 즉시 0/0/0, 새로고침 후에도 0/0/0 | **통과** — 즉시 0/0/0, 새로고침 후 0/0/0, 저장값 `{"wins":0,"losses":0,"draws":0}` |
| 6. Tab/Enter(Space)만으로 한 라운드와 초기화 | 키보드만으로 가능 | **통과** — Tab 순서 가위 → 바위 → 보 → 전적 초기화, Enter로 합계 0→1, Space로 1→2, 초기화 버튼에서 Enter로 0/0/0 |

6단계 모두 기대대로 동작했다. 이상 없음.
