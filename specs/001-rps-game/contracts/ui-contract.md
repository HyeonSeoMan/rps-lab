# UI Contract: 가위바위보 화면

테스트(React Testing Library)와 수동 검증이 의존하는 화면 요소의 계약이다. 쿼리는 role과 접근 가능한 이름을 사용한다.
UI 문구와 이모지는 사용자 승인 완료(2026-11-05)다.

## 요소

| 요소 | role / 접근 가능한 이름 | 동작 | FR |
|---|---|---|---|
| 페이지 제목 | heading level 1 — "가위바위보" | 정적 | — |
| 선택 버튼 3개 | group — "손 모양 선택" 안의 button — "가위", "바위", "보" | 클릭/탭/Enter/Space로 라운드 1회 진행. 항상 활성 | FR-001, 006, 011, 012 |
| 라운드 결과 영역 | region — "최근 라운드 결과" | 사용자 선택 / 승패 / 컴퓨터 선택의 좌우 대결 구조(아래 "결과 영역 구조") | FR-004 |
| 결과 문장 | `role="status"` — 결과 영역 안에 **1개**, 화면에는 보이지 않고 보조기술이 읽는다 | 초기: "가위, 바위, 보 중 하나를 선택하세요". 진행 후: "나: {내 선택} · 컴퓨터: {컴퓨터 선택} — {승리!/패배/무승부}" | FR-004 |
| 전적 표시 | list — "누적 전적", listitem 3개. 각 항목은 라벨(`승`/`패`/`무`)과 숫자를 **별도 요소**로 담으며 읽히는 텍스트는 "승 {n}", "패 {n}", "무 {n}" | 항상 표시 | FR-005 |
| 전적 초기화 버튼 | button — "전적 초기화" | 클릭 시 즉시 0/0/0 + 결과 영역 초기 상태. 확인 대화상자 없음 | FR-008 |

## 상태: 복원 전 (skeleton)

서버 렌더와 하이드레이션 첫 렌더에는 제목과 빈 영역(`aria-busy="true"`)만 보인다. 전적 값, 선택 버튼, 초기화 버튼은
**존재하지 않는다**. 따라서 복원 전에는 입력이 불가능하고 잘못된 0/0/0이 표시되지 않는다. 복원(마운트 시 동기 읽기)이 끝나면
`GameBoard`가 렌더된다. 요소 표는 복원 후 화면을 기준으로 한다.

## 결과 영역 구조 (복원 후)

1. **좌우 대결 구조**: 왼쪽 "나"(사용자 선택의 손 이모지와 이름), 가운데 "VS"와 승패, 오른쪽 "컴퓨터"(컴퓨터 선택의 손 이모지와 이름) 순서로 표시한다.
2. **승패는 텍스트로 구분**한다: "승리!", "패배", "무승부". 색상(초록/빨강/회색)은 보조 수단이며 색만으로 구분하지 않는다. 가운데 요소에는 `data-outcome="win|lose|draw"`(첫 라운드 전에는 `none`)가 붙는다.
3. **초기 상태(첫 라운드 전)**: 선택 결과가 없는 중립 화면이다. 양쪽 손 영역에 "?"를 표시하고 이름 줄과 승패 문구는 비운다(VS는 유지). 결과 영역 아래에 시각용 안내 문구 "가위, 바위, 보 중 하나를 선택하세요"를 `aria-hidden`으로 표시하며, 첫 라운드 이후에는 문구를 지우되 높이는 유지한다.
4. **중복 낭독 방지**: 결과를 읽는 주체는 `role="status"` 문장 하나뿐이다. 시각용 대결 영역(손, 이름, VS, 승패)과 시각용 안내 문구는 `aria-hidden="true"`로 접근성 트리에서 제외한다. 손 이모지는 장식이다.
5. 결과 영역에는 가장 최근 라운드만 표시하고 이력 목록은 두지 않는다. (FR-004)

## 전적 접근성 대조

| 기존 요구 | 구현 | 확인 |
|---|---|---|
| 전적이 항상 화면에 표시된다 (FR-005, AC-005) | 항목 3개를 항상 렌더 | UI 테스트 |
| "승 {n}" 형태로 라벨과 값이 함께 읽힌다 (이 문서의 기존 요소 표) | `<li>` 안에 라벨 요소와 숫자 요소가 순서대로 들어 있어 읽히는 텍스트가 "승 {n}" | UI 테스트(`textContent` 기준), 브라우저 접근성 트리에서 `listitem` 안 `승` → `0` 순서 확인 |
| 전적 묶음의 의미가 전달된다 | `list`에 접근 가능한 이름 "누적 전적" | UI 테스트(role=list, name), 접근성 트리 확인 |
| 합계·증가 규칙 (AC-006, AC-007) | 값 변경 없음 | UI 테스트 |

- 전적 숫자는 live region이 아니다. 라운드 후 전적 변화는 자동 낭독되지 않고, 사용자가 전적 목록을 탐색해 읽는다. 기존 요구사항은 전적의 "표시"만 요구하므로 변경하지 않는다.
- 실제 스크린리더(VoiceOver, TalkBack)에서의 낭독 확인은 수동 검증 항목이다.

## 규칙

- 선택 버튼과 초기화 버튼은 네이티브 `<button>`이며 `onClick`만 사용한다(터치/포인터/키 별도 핸들러 없음).
- 복원이 끝난 뒤에는 라운드 처리 중 버튼을 비활성화하거나 입력을 지연시키지 않는다. (FR-006)
- 모든 버튼 렌더 크기는 최소 44×44 CSS px. (FR-009)
- 가로 스크롤이 생기지 않아야 한다(폭 320px~). 전적 숫자가 커져도 줄바꿈/축소로 수용한다. (AC-010, AC-015)
- 선택 버튼의 이모지(✌️✊✋)는 장식이며 `aria-hidden`. 접근 가능한 이름은 텍스트다. (검토 요청 2)
- 문서 언어는 `lang="ko"`.
- 화면 어디에서도 네트워크 요청을 발생시키지 않는다. (FR-010)
