# UI Contract: 가위바위보 화면

테스트(React Testing Library)와 수동 검증이 의존하는 화면 요소의 계약이다. 쿼리는 role과 접근 가능한 이름을 사용한다.
UI 문구와 이모지는 사용자 승인 완료(2026-11-05)다.

## 요소

| 요소 | role / 접근 가능한 이름 | 동작 | FR |
|---|---|---|---|
| 페이지 제목 | heading level 1 — "가위바위보" | 정적 | — |
| 선택 버튼 3개 | button — "가위", "바위", "보" | 클릭/탭/Enter/Space로 라운드 1회 진행. 항상 활성 | FR-001, 006, 011, 012 |
| 라운드 결과 영역 | `role="status"` | 초기: "가위, 바위, 보 중 하나를 선택하세요". 진행 후: "나: {내 선택} · 컴퓨터: {컴퓨터 선택} — {승리!/패배/무승부}" | FR-004 |
| 전적 표시 | "승 {n}", "패 {n}", "무 {n}" 세 항목 (라벨과 값이 함께 읽힘) | 항상 표시 | FR-005 |
| 전적 초기화 버튼 | button — "전적 초기화" | 클릭 시 즉시 0/0/0 + 결과 영역 초기 상태. 확인 대화상자 없음 | FR-008 |

## 상태: 복원 전 (skeleton)

서버 렌더와 하이드레이션 첫 렌더에는 제목과 빈 영역(`aria-busy="true"`)만 보인다. 전적 값, 선택 버튼, 초기화 버튼은
**존재하지 않는다**. 따라서 복원 전에는 입력이 불가능하고 잘못된 0/0/0이 표시되지 않는다. 복원(마운트 시 동기 읽기)이 끝나면
`GameBoard`가 렌더된다. 요소 표는 복원 후 화면을 기준으로 한다.

## 규칙

- 선택 버튼과 초기화 버튼은 네이티브 `<button>`이며 `onClick`만 사용한다(터치/포인터/키 별도 핸들러 없음).
- 복원이 끝난 뒤에는 라운드 처리 중 버튼을 비활성화하거나 입력을 지연시키지 않는다. (FR-006)
- 모든 버튼 렌더 크기는 최소 44×44 CSS px. (FR-009)
- 가로 스크롤이 생기지 않아야 한다(폭 320px~). 전적 숫자가 커져도 줄바꿈/축소로 수용한다. (AC-010, AC-015)
- 선택 버튼의 이모지(✌️✊✋)는 장식이며 `aria-hidden`. 접근 가능한 이름은 텍스트다. (검토 요청 2)
- 문서 언어는 `lang="ko"`.
- 화면 어디에서도 네트워크 요청을 발생시키지 않는다. (FR-010)
