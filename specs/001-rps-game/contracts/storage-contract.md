# Storage Contract: 전적 저장

| 항목 | 값 |
|---|---|
| 저장소 | `window.localStorage` (같은 브라우저·같은 출처에 한정, 서버 전송 없음) |
| 키 | `rps-lab:score` |
| 값 | JSON 문자열 `{"wins": <int>, "losses": <int>, "draws": <int>}` |
| 쓰기 시점 | 전적이 바뀔 때(라운드 진행, 초기화)만. 마운트 직후에는 쓰지 않음. 읽기가 성공(또는 키 없음/값 손상)한 경우에만(`writable=true`) |
| 읽기 시점 | `GameBoard` 마운트 시 1회(동기). 서버 렌더에서는 읽지 않음 |
| 저장 제외 | 최근 라운드 결과, 기타 모든 값 |

## 유효성 규칙 (`parseScore`)

값을 채택하려면 모두 만족해야 한다.

1. 문자열이며 유효한 JSON 객체
2. `wins`, `losses`, `draws`가 모두 존재
3. 세 값 모두 0 이상의 안전한 정수 (`Number.isSafeInteger`, 음수·소수·NaN·문자열 불가)

위반 시 → `null` 반환 → 화면은 0/0/0으로 시작 (저장값은 다음 변경 시 덮어씀). 추가 키는 무시한다.

## 오류 처리

| 상황 | 동작 | AC |
|---|---|---|
| `localStorage` 접근 예외 / 사용 불가 | `getBrowserStorage()`가 `null` 반환 → 복원·저장 생략(`writable=false`), 메모리로 계속 진행 | AC-020, 021 |
| `getItem` 예외 | 0/0/0으로 시작하고 **이번 세션에서는 저장하지 않음**(읽지 못한 유효 데이터를 덮어쓰지 않기 위함) | AC-020 |
| `setItem` 예외 (용량, 비공개 모드 등) | 무시, 오류 메시지 없음, 화면 전적은 정상 누적 | AC-021 |
| 키 없음 | 0/0/0, `writable=true` | AC-005 |
| 값 손상/유효하지 않음 | 0/0/0, `writable=true`. 다음 변경 때 정상 값으로 대체 | AC-020 |
| 다중 탭 | 마지막 쓰기 우선(동기화 미보장, 승인된 가정) | — |

## 호환성

키 이름 `rps-lab:score`와 스키마가 바뀌면 이전 값은 유효성 검사로 걸러져 0/0/0이 된다. 스키마 버전 필드는 현재 도입하지 않는다(YAGNI).
