**Created**: 2026-11-05

**Status**: Approved (2026-11-05, 사용자 최종 승인 — FR 12개, AC 22개, 가정 및 경계 조건 확정)

**Input**: User description: "사용자가 혼자서 컴퓨터와 가위바위보를 즐길 수 있는 반응형 웹사이트. 가위/바위/보 선택, 컴퓨터 무작위 선택, 승/패/무 판정, 라운드 결과 표시, 누적 전적 표시, 연속 진행, 모바일·데스크톱 지원, 로그인/DB/백엔드 불필요."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 한 라운드 플레이하고 결과 확인 (Priority: P1)

사용자가 사이트에 접속해 가위, 바위, 보 중 하나를 선택하면 컴퓨터도 하나를 무작위로 선택하고,
두 선택과 승리/패배/무승부 결과가 화면에 표시된다.

**Why this priority**: 게임의 핵심 가치이며, 이것만 구현해도 플레이 가능한 MVP가 된다.

**Independent Test**: 페이지를 열고 세 선택지 중 하나를 눌러 결과(양쪽 선택 + 판정)가 표시되는지
확인한다. 판정 규칙은 모든 9가지 조합으로 검증한다.

**Acceptance Scenarios**:

1. **AC-001** — **Given** 게임 화면이 열려 있다, **When** 페이지를 처음 본다, **Then** 가위·바위·보
   세 선택지가 모두 보이고 선택 가능하다. *(FR-001)*
2. **AC-002** — **Given** 게임 화면이 열려 있다, **When** 사용자가 선택지 하나를 누른다,
   **Then** 컴퓨터의 선택, 사용자의 선택, 판정 결과가 화면에 표시된다. *(FR-001, FR-002, FR-004)*
3. **AC-003** — **Given** 사용자와 컴퓨터의 선택 조합이 주어진다, **When** 판정한다,
   **Then** 가위→보, 바위→가위, 보→바위는 이긴 쪽이 승리하고 같은 선택은 무승부이다.
   9가지 조합 모두 기대 결과와 일치한다. *(FR-003)*
4. **AC-004** — **Given** 컴퓨터가 선택을 한다, **When** 충분히 많은 라운드(예: 3,000회, 시드 고정 또는
   무작위 소스 주입)를 시뮬레이션한다, **Then** 가위·바위·보 세 값이 모두 나타난다.
   *(FR-002)*

### User Story 2 - 누적 전적 확인 (Priority: P1)

사용자는 지금까지의 승리/패배/무승부 횟수를 항상 화면에서 볼 수 있다.

**Why this priority**: 요구사항에 명시된 핵심 기능이며 재미를 주는 피드백이다.

**Independent Test**: 여러 라운드를 진행하며 전적 숫자가 결과와 일치하게 증가하는지 확인한다.

**Acceptance Scenarios**:

1. **AC-005** — **Given** 저장된 전적이 없는 첫 접속이다, **When** 화면을 본다, **Then** 승 0 / 패 0 / 무 0이 표시된다.
   *(FR-005)*
2. **AC-006** — **Given** 현재 전적이 있다, **When** 한 라운드가 끝난다, **Then** 해당 라운드 결과에
   해당하는 항목 하나만 정확히 1 증가하고 나머지는 변하지 않는다. *(FR-005)*
3. **AC-007** — **Given** 전적이 0 / 0 / 0인 상태(첫 접속 또는 초기화 직후)에서 N라운드를 진행했다,
   **When** 전적을 본다, **Then** 승 + 패 + 무 = N 이다. *(FR-005)*

---

### User Story 3 - 연속 플레이 (Priority: P1)

사용자는 새로고침이나 별도 조작 없이, 원하는 속도로 계속해서 다음 라운드를 진행할 수 있다.

**Why this priority**: "연속해서 게임을 진행"은 명시 요구사항이다.

**Independent Test**: 결과 표시 직후 바로(빠르게 연속으로도) 선택지를 눌러 매번 다음 라운드가 진행되는지 확인한다.

**Acceptance Scenarios**:

1. **AC-008** — **Given** 한 라운드 결과가 표시되어 있다, **When** 사용자가 다시 선택지를 누른다,
   **Then** 새 라운드가 진행되고 결과 표시가 새 라운드 내용으로 갱신되며 이전 라운드 결과는 목록 등으로
   남지 않는다. *(FR-004, FR-006)*
2. **AC-009** — **Given** 여러 라운드를 진행했다, **When** 이어서 플레이한다,
   **Then** 누적 전적이 이전 라운드 결과를 포함해 계속 누적된다. *(FR-005, FR-006)*
3. **AC-022** — **Given** 게임 화면이다, **When** 사용자가 서로 다른 입력(클릭·탭·키 입력)을 N회(N ≥ 2,
   예: 0.1초 간격 3회) 빠르게 연속으로 수행한다, **Then** 모든 입력이 각각 하나의 라운드로 처리되어
   전적 합계가 정확히 N 증가하고 어떤 입력도 무시되거나 차단되지 않으며, 결과 영역에는 마지막 라운드가
   표시된다. *(FR-006, FR-011)*

### User Story 4 - 모바일·데스크톱에서 사용 (Priority: P2)

사용자는 스마트폰과 데스크톱 브라우저 모두에서 불편 없이 게임을 한다.

**Why this priority**: 필수 요구사항이지만 게임 로직이 먼저 성립해야 의미가 있다.

**Independent Test**: 좁은 화면(폭 320px)과 넓은 화면(폭 1280px)에서 모든 기능을 수행해 본다.

**Acceptance Scenarios**:

1. **AC-010** — **Given** 폭 320px 화면이다, **When** 게임 화면을 본다, **Then** 가로 스크롤 없이
   선택지·결과·전적이 모두 보이고 사용 가능하다. *(FR-009)*
   (Manual: 뷰포트 폭 320px에서 한 라운드 플레이 후 스크롤바 유무와 요소 가림 여부를 기록)
2. **AC-011** — **Given** 폭 1280px 이상 화면이다, **When** 게임 화면을 본다, **Then** 내용이
   깨지거나 겹치지 않고 모든 기능이 사용 가능하다. *(FR-009)*
   (Manual: 뷰포트 폭 1280px에서 동일 절차 수행 후 결과 기록)
3. **AC-012** — **Given** 터치 기기이다, **When** 선택지를 누른다, **Then** 각 선택지와 전적 초기화 버튼의 터치 영역은
   최소 44×44 CSS px 이상이다. *(FR-009)*
   (Manual: 개발자 도구로 각 버튼의 렌더링 크기를 측정해 기록)
4. **AC-013** — **Given** 키보드만 사용한다, **When** Tab/Enter(또는 Space)로 조작한다,
   **Then** 선택지를 선택하고 라운드를 진행하며 전적 초기화 버튼도 조작할 수 있다. *(FR-012)*

---

### User Story 5 - 전적 유지와 초기화 (Priority: P2)

사용자는 페이지를 새로고침하거나 같은 브라우저로 다시 접속해도 이전 누적 전적을 이어서 보고,
원할 때 버튼 하나로 전적을 0으로 되돌릴 수 있다.

**Why this priority**: 핵심 플레이 이후의 편의 기능이며, 서버 없이 같은 브라우저 안에서만 동작한다.

**Independent Test**: 몇 라운드 플레이 후 새로고침하여 전적이 유지되는지, 초기화 버튼으로 0이 되고
새로고침 후에도 0인지 확인한다.

**Acceptance Scenarios**:

1. **AC-017** — **Given** 누적 전적이 있다, **When** 페이지를 새로고침하거나 같은 브라우저로 다시
   접속한다, **Then** 직전 누적 승/패/무 값이 그대로 표시된다. *(FR-007)*
2. **AC-018** — **Given** 누적 전적이 있다, **When** 사용자가 전적 초기화 버튼을 누른다,
   **Then** 확인 절차 없이 즉시 승 0 / 패 0 / 무 0이 표시되고 라운드 결과 영역이 아직 라운드가 진행되지
   않은 초기 상태(이전 선택·결과가 보이지 않음)로 돌아간다. *(FR-008)*
3. **AC-019** — **Given** 전적을 초기화했다, **When** 페이지를 새로고침한다,
   **Then** 전적은 여전히 0 / 0 / 0이다. *(FR-007, FR-008)*
4. **AC-020** — **Given** 저장된 전적을 읽을 수 없다(브라우저 저장소 사용 불가, 손상, 음수·숫자 아님 등
   유효하지 않은 값), **When** 페이지를 연다, **Then** 오류 없이 0 / 0 / 0으로 시작하고 게임을 정상
   진행할 수 있다. *(FR-007)*
5. **AC-021** — **Given** 브라우저 저장소를 사용할 수 없다, **When** 라운드를 진행한다,
   **Then** 현재 화면에서는 전적이 정상 누적되고 오류 메시지로 게임이 중단되지 않는다. *(FR-007)*

---

### Edge Cases

- **빠른 연속 입력 / 더블 클릭·탭**: 하나의 입력은 정확히 한 라운드만 만들고, 빠르게 이어진 별개의 입력은
  각각 한 라운드씩 모두 처리된다(더블 클릭 = 입력 2회 = 2라운드). (AC-014, AC-022, FR-006, FR-011)
- **같은 선택 연속**: 사용자나 컴퓨터가 같은 값을 여러 번 연속 선택해도 정상 동작한다. 컴퓨터가
  이전 선택을 피하거나 사용자 선택에 반응해서는 안 된다. (AC-004, FR-002)
- **전적 숫자가 커질 때**: 세 자릿수(예: 999) 이상에서도 화면 레이아웃이 깨지지 않는다. (AC-015, FR-005)
- **JavaScript 비활성/로딩 실패**: MVP에서는 지원하지 않는다(Assumptions 참고).
- **새로고침 / 탭 종료 후 재접속**: 같은 브라우저에서는 누적 전적이 유지된다. (AC-017, FR-007)
- **저장 데이터 이상**: 저장소 사용 불가, 손상, 유효하지 않은 값이면 0으로 시작하고 게임은 계속된다.
  (AC-020, AC-021, FR-007)
- **초기화 직후**: 초기화 후 즉시 다음 라운드를 진행해도 전적은 0부터 정확히 누적된다. (AC-007, AC-018, FR-008)
- **다른 브라우저/기기**: 전적은 공유되지 않는다. (FR-010)
- **네트워크 단절**: 서버 통신이 없으므로 접속 후에는 게임 진행에 영향이 없다. (FR-010)

## Requirements *(mandatory)*

### Functional Requirements

각 FR은 연결된 AC로 검증한다. 검증 방식은 Constitution VII에 따라 자동 테스트(Auto) 또는 수동 절차(Manual)로 명시한다.

- **FR-001**: 사용자는 가위, 바위, 보 세 선택지 중 하나를 한 번의 조작(클릭/탭)으로 선택할 수 있어야
  한다. — AC-001, AC-002 (Auto: UI 테스트)
- **FR-002**: 컴퓨터는 매 라운드 가위·바위·보 중 하나를 무작위로 선택해야 하며, 사용자의 선택이나
  이전 라운드에 영향을 받아서는 안 된다. — AC-002, AC-004 (Auto: 단위 테스트)
- **FR-003**: 시스템은 다음 규칙으로 결과를 정확히 판정해야 한다: 가위는 보를, 바위는 가위를, 보는
  바위를 이긴다. 같은 선택이면 무승부이다. — AC-003 (Auto: 단위 테스트, 9조합 전수)
- **FR-004**: 시스템은 매 라운드 사용자의 선택, 컴퓨터의 선택, 판정 결과(승리/패배/무승부)를 화면에
  표시해야 한다. 표시 대상은 가장 최근 라운드의 결과뿐이며 라운드 이력 목록은 제공하지 않는다. —
  AC-002, AC-008 (Auto: UI 테스트)
- **FR-005**: 시스템은 승리, 패배, 무승부의 누적 횟수를 항상 화면에 표시해야 하며, 저장된 전적이 없을 때 초기값은 모두 0이고
  라운드가 끝날 때마다 해당 결과의 횟수만 정확히 1 증가해야 한다. — AC-005, AC-006, AC-007, AC-009,
  AC-015 (AC-005~007, AC-009: Auto 단위 + UI 테스트, AC-015: Manual)
- **FR-006**: 사용자는 라운드 종료 후 별도의 새로고침이나 추가 조작 없이 바로 다음 라운드를 진행할 수
  있어야 하며, 라운드 수에 제한이 없어야 한다. 시스템은 라운드 사이에 입력을 지연·잠금·제한하지 않고,
  빠르게 연속된 정상 입력도 차단해서는 안 된다. — AC-008, AC-009, AC-022 (Auto: UI 테스트)
- **FR-007**: 누적 전적은 같은 브라우저에서 페이지 새로고침이나 재접속 후에도 유지되어야 한다. 서버에
  저장해서는 안 되며, 저장된 값을 읽을 수 없거나 유효하지 않으면 0으로 시작하고, 저장이 불가능해도
  게임 진행이 중단되어서는 안 된다. — AC-017, AC-019, AC-020, AC-021 (Auto: 단위 + UI 테스트)
- **FR-008**: 사용자는 전적 초기화 버튼으로 누적 전적을 확인 절차 없이 즉시 0으로 되돌릴 수 있어야
  하며, 초기화된 값도 FR-007에 따라 유지되어야 한다. 초기화 시 라운드 결과 영역도 아직 라운드가
  진행되지 않은 초기 상태(이전 선택·결과가 보이지 않음)로 돌아간다. — AC-018, AC-019 (Auto: UI 테스트)
- **FR-009**: 화면은 모바일(최소 폭 320px)과 데스크톱(폭 1280px 이상) 환경에서 가로 스크롤 없이
  모든 기능을 사용할 수 있어야 하며, 선택지와 전적 초기화 버튼의 터치 영역은 최소 44×44 CSS px 이상이어야 한다. —
  AC-010, AC-011, AC-012 (Manual: AC-010~012의 절차와 결과를 기록. 자동화 가능 시 Plan에서 대체 가능)
- **FR-010**: 게임은 로그인, 데이터베이스, 백엔드 서버 없이 동작해야 하며 사용자 개인정보를 수집하지
  않아야 한다. 전적은 사용자 브라우저 안에만 존재하며 다른 브라우저나 기기와 공유되지 않는다. — AC-016 (Manual: 네트워크 요청 점검 후 결과 기록)
- **FR-011**: 하나의 사용자 입력(클릭 1회, 탭 1회, 키보드 활성화 1회)은 정확히 한 라운드만 생성해야
  한다. 하나의 입력이 이벤트 중복 등으로 라운드를 두 번 이상 진행하거나 전적을 중복 증가시켜서는
  안 된다. 이 요구사항은 입력을 막는 근거가 아니며, 별개의 입력은 FR-006에 따라 모두 각각 처리된다.
  — AC-014, AC-022 (Auto: UI 테스트)
- **FR-012**: 선택지와 전적 초기화 버튼은 키보드로 포커스·조작할 수 있어야 한다. — AC-013 (Auto: UI 테스트)

### Additional Acceptance Criteria

- **AC-014** *(FR-011)*: **Given** 게임 화면이다, **When** 선택지를 하나의 입력으로 조작한다(마우스 클릭 1회,
  터치 탭 1회, 키보드 활성화 1회 각각), **Then** 정확히 한 라운드만 진행되고 전적 합계가 정확히 1 증가한다.
  터치 탭이 클릭 이벤트를 함께 발생시키는 환경에서도 동일하다. (Auto: UI 테스트)
- **AC-015** *(FR-005)*: **Given** 전적 값이 세 자릿수 이상이다, **When** 화면을 본다,
  **Then** 폭 320px에서도 숫자가 잘리거나 레이아웃이 깨지지 않는다. (Manual 또는 Auto)
- **AC-016** *(FR-010)*: **Given** 페이지가 로드된 상태이다, **When** 여러 라운드를 플레이한다,
  **Then** 게임 진행(라운드 진행, 전적 저장·초기화)을 위한 서버 요청이 발생하지 않고 로그인 화면이 요구되지 않는다.
  (Manual: 브라우저 개발자 도구의 Network 탭 점검 결과 기록)

### Key Entities *(include if feature involves data)*

- **선택(Choice)**: 가위, 바위, 보 중 하나.
- **결과(Outcome)**: 사용자 관점의 승리, 패배, 무승부 중 하나.
- **라운드(Round)**: 사용자 선택, 컴퓨터 선택, 결과로 이루어진 한 번의 대결.
- **전적(Score)**: 승리, 패배, 무승부 각각의 누적 횟수(0 이상의 정수). 같은 브라우저 안에 유지된다.

## Assumptions (가정)

- 대상 사용자는 한 명이며 한 기기에서 혼자 플레이한다. 멀티플레이, 계정, 랭킹은 범위 밖이다.
- UI 문구는 한국어로 제공한다.
- 컴퓨터의 세 선택은 균등한 확률(각 1/3)로 선택한다.
- 결과는 사용자 선택 직후 즉시 표시한다(애니메이션·카운트다운 연출 없음).
- 사운드, 난이도, 라운드 제한(몇 판 몇 승제), 다크 모드, 다국어는 MVP 범위 밖이다.
- 지원 환경은 최신 버전의 주요 브라우저(Chrome, Safari, Firefox, Edge)의 모바일·데스크톱이다.
- JavaScript 비활성 환경은 지원하지 않는다.
- 최소 지원 화면 폭은 320px, 터치 영역 최소 크기 44×44 CSS px는 일반적인 접근성 관례를 따른 값이다.

### 승인된 가정 (사용자 승인 완료)

위 가정 전체와 키보드 접근성(FR-012), 44×44 CSS px 터치 영역(FR-009) 기준을 사용자가 승인했다.

### 승인된 추가 가정 (Q1~Q3 반영 중 생긴 항목, 사용자 승인 완료)

- 라운드 결과 영역(가장 최근 라운드)은 저장하지 않는다. 새로고침 후에는 전적만 복원되고 결과 영역은
  초기 상태로 시작한다.
- 전적 초기화는 전적과 라운드 결과 영역을 모두 초기 상태로 되돌린다.
- 같은 브라우저에서 여러 탭을 동시에 열었을 때 탭 간 실시간 동기화는 보장하지 않는다.
- 초기화 버튼은 확인 절차가 없으므로 실수 조작에 대한 되돌리기(undo)는 제공하지 않는다.
