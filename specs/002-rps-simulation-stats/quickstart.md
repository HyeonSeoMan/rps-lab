# Quickstart: v2 구현 후 검증 가이드

구현이 끝난 뒤 v2가 Spec대로 동작하는지 확인하는 **실행·검증 안내**다. 구현 방법은 [plan.md](plan.md), 데이터는 [data-model.md](data-model.md), 계약은 [contracts/](contracts/)를 본다. 수동 검증 결과는 구현 완료 시 `specs/002-rps-simulation-stats/verification.md`에 일시·환경·결과로 기록한다(Constitution VII).

## 1. 사전 준비

```bash
npm install           # devDependency fake-indexeddb 포함(승인됨, 설치는 구현 단계)
npm run dev           # http://localhost:3000 (게임) · /history (기록·통계)
```

## 2. 품질 게이트 (Constitution VIII)

```bash
npm run typecheck && npm run lint && npm test
grep -rn "eslint-disable" src     # 결과 없음이어야 함 (v1 방침 유지)
grep -rn "localStorage" src       # 결과 없음이어야 함 (FR2-020, AC2-045~047)
```
테스트 이름은 `AC2-0xx: …`, `FR2-0xx: …`로 시작해 Spec과 grep으로 추적한다.

## 4. 성능 측정 절차 (P-8: 방법만 승인, 수치는 측정 후 합의)

1. **환경 기록**: 기기·OS·브라우저 버전. 기준은 확장 프로그램 없는 최신 Chrome, 캐시 비움. DevTools CPU 4배 스로틀로도 측정하고 실제 모바일 기기 1대를 수동 확인한다.
2. **시드 데이터**: 규모 1,000 / 10,000 / 100,000건. 앱 코드가 아니라 DevTools 콘솔에서 [storage-contract](contracts/storage-contract.md) 스키마대로 `battles`와 `meta.stats`를 일괄 기록하는 스니펫을 쓴다. 시드 후 `meta.stats` 합과 `battles` 수가 같아야 한다.
3. **지표** (각 5회 이상, 중앙값·최댓값 기록):
   - ① `/history` 진입 → 통계와 첫 20건 표시 (`performance.measure`)
   - ② 이전/다음 클릭 → 갱신
   - ③ 자동 1,000회 실행 중 50ms를 넘는 긴 작업 횟수·최대 길이 (`PerformanceObserver('longtask')`)
   - ④ 중지 클릭 → 기록 증가가 멈출 때까지
   - ⑤ 즉시 결과 100·1,000회 완료까지, 애니메이션 완료까지
4. **판정**: 절대값은 측정 후 사용자와 합의한다. 환경에 덜 민감한 상대 기준을 우선한다(예: 100,000건의 첫 화면이 1,000건의 몇 배 이내인지, 긴 작업 50ms 초과 0회).
5. 즉시 결과 1,000회가 길면 P-6 메모에 따라 중지·진행 표시 추가를 사용자와 재검토한다.

## 5. 저장 실패 만들기 (개발자 도구)

DevTools 콘솔(앱이 열린 탭)에서 아래 중 하나를 사용한다. 해제하려면 새로고침한다.

| 목적 | 방법 |
|---|---|
| 쓰기만 실패(용량 초과 모사) | `IDBObjectStore.prototype.add = () => { throw new DOMException("quota", "QuotaExceededError") }` |
| 읽기 실패 | 브라우저 설정에서 해당 사이트의 데이터 저장을 차단하거나(Chrome: 설정 → 개인정보 및 보안 → 사이트 설정 → 사이트 데이터) 저장소를 쓸 수 없는 시크릿 모드로 연다. 앱 로드 전에 막아야 하므로 콘솔 패치로는 만들 수 없다 |
| 복구 | 위 패치를 되돌리는 코드를 실행(`delete IDBObjectStore.prototype.add` 후 원래 함수 복원) 또는 새로고침 후 "저장 다시 시도" |

### 7.2 로컬 사전 확인 (배포 빌드)
1. 배포용 basePath 환경변수를 지정해 `next build`를 실행한다(변수 이름은 Tasks T-D1에서 확정).
2. `out/`을 **`/rps-lab/` 하위 경로로** 서빙하는 정적 서버로 연다. `next start`는 정적 내보내기와 함께 쓰지 않는다. 디렉터리 URL의 슬래시 리다이렉트와 `404.html` 동작을 확인할 수 있는 정적 서버를 쓴다.
