# UI Contract: 게임 · 기록·통계 화면 (v2)

테스트(React Testing Library)와 수동 검증이 의존하는 화면 요소의 계약이다. 쿼리는 role과 접근 가능한 이름을 사용한다.
**시각·상태별 레퍼런스는 `docs/references/rps-lab-v2-ui.html`** 이고, **기능 동작과 데이터 처리 규칙은 Spec이 우선**한다. 최종 HTML의 샘플 숫자·미리보기 도구는 계약이 아니다.
v1 계약(`specs/001-rps-game/contracts/ui-contract.md`)의 구조를 유지·확장하며 v1 문서는 변경하지 않는다.

**승인 상태 표기**: ✅ = 사용자 승인 완료(최종 HTML의 문구, 또는 2026-11-05에 사용자가 지정·승인한 문구). (현재 승인 대기 중인 항목은 없다.) 구현 중 새로 추가하거나 바꾸는 문구는 Spec Assumptions에 따라 별도 검토·승인을 받는다.

## 4. 전적 초기화 확인 대화상자 (U5: 화면 내 커스텀)

`role="alertdialog"`, `aria-modal="true"`, `aria-labelledby`(제목 "전적을 초기화할까요?" ✅), `aria-describedby`(본문 "전체 전적과 모든 대결 기록이 삭제되며 되돌릴 수 없어요. 마지막 대결 결과도 함께 지워져요." ✅). 버튼 "취소" ✅, "전체 삭제" ✅.

**구현 단계 필수 요구사항** (최종 HTML에서 구현·검증한 4가지를 실제 앱에서 다시 구현하고 테스트한다):

| # | 요구사항 | 자동(jsdom) | 수동 |
|---|---|---|---|
| 1 | 열릴 때 포커스를 대화상자 안(취소 버튼)으로 이동 | 열기 직후 `document.activeElement` 확인 | M-05 |
| 2 | 열려 있는 동안 포커스가 대화상자 안에 머무름: 앱 헤더·본문에 `inert`, Tab/Shift+Tab 순환(`inert` 미지원 환경 보강) | Tab ×N·Shift+Tab 후 포커스가 대화상자 안인지 확인. **jsdom은 `inert`를 구현하지 않으므로 속성 존재만 확인** | M-05 실제 `inert` 동작 |
| 3 | `Esc`로 닫기(취소와 동일, 데이터 변경 없음) | 키 입력 후 닫힘·전적 불변 | M-05 |
| 4 | 닫힌 뒤 연 버튼("전적 초기화")으로 포커스 복원. 진행 중이라 버튼이 비활성이면 진행 안내 문구로 이동했다가 끝나면 복원 | 닫힌 직후·초기화 종료 후 포커스 확인 | M-05 |

초기화 진행 중: "초기화하는 중이에요. 잠시 기다려 주세요." ✅(시각 표시, live 아님, 버튼 `aria-busy`, 낭독 없음). 성공: 대표 live region이 6절 6번 문장을 낭독. 실패: `role="alert"` "초기화하지 못했어요 / 전적과 기록은 아무것도 지워지지 않았어요. 잠시 후 다시 시도해 주세요." ✅. 초기화 중에는 "저장 다시 시도"를 비활성화하고, 재시도 중에는 "전적 초기화"를 비활성화한다(G-6).

문구는 최종 HTML ✅. **낭독 책임은 6절의 책임표를 따른다**(같은 사건을 두 영역이 낭독하지 않는다).

| 상태 | 표시 | 낭독 | 내용 | 동작 |
|---|---|---|---|---|
| 저장 실패(수동 저장 실패로 저장 불가 진입) | 알림 박스 | `role="alert"` — 이 사건의 유일한 상태 낭독(결과 문장에는 꼬리표만) | "기록을 저장하지 못했어요 / 저장 불가 상태예요. 지금부터의 직접 대결은 연습 대결이며 전적과 기록에 반영되지 않아요. 자동 대결은 저장을 복구한 뒤에 할 수 있어요." | button "저장 다시 시도" |
| 저장 실패(자동 대결 중단으로 저장 불가 진입) | 같은 알림 박스 | **live 속성 없음** — 낭독은 6절 5번 문장이 담당 | 위와 같음 | button "저장 다시 시도" |
| 읽기 실패 | 알림 박스 | `role="alert"` | "저장된 전적을 불러오지 못했어요 / 전적이 0이라는 뜻은 아니에요. 저장을 다시 시도하기 전까지는 연습 대결만 할 수 있어요." | button "저장 다시 시도". 전적 "—" |
| 재시도 중 | 박스, 버튼 `aria-busy` + `disabled` "다시 시도하는 중…" | live 없음 — 대표 live region이 낭독 | "저장소를 다시 확인하는 중이에요" | |
| 복구됨 | 박스 | live 없음 — 대표 live region이 낭독 | "저장이 복구되었어요 / 지금부터 대결이 기록돼요. 복구 전의 연습 대결은 저장되지 않아요." | 해제 시점은 아래(승인됨) |
| 재시도 실패 | 박스 유지(저장 불가 상태 유지) | `role="alert"` ✅ `저장을 다시 시도했지만 실패했어요. 연습 대결은 계속할 수 있어요.`(낭독 전용, 시각적으로 숨김) | 기존 알림 박스 문구 유지(시각 변경 없음) | button "저장 다시 시도"(다시 활성) |

규칙: 저장 불가 상태에서는 사용자가 **명시적으로 "저장 다시 시도"에 성공하기 전까지** 새 수동 대결을 모두 연습 대결로 처리하고 대결마다 자동 재시도하지 않는다(P-14). 이 상태는 **앱 내 페이지 이동 후 복귀해도 유지**되고 새로고침하면 저장소를 다시 확인해 정해진다(plan 5절, G-2). 복구 후 연습 결과는 지워 중립 화면으로 돌아간다(AC2-070).

### "복구됨" 안내의 해제 시점 ✅ (승인 2026-11-05: 이벤트 기반)

복구됨 안내는 다음 중 **먼저 오는 사건**에서 해제한다: ① 다음 **확정 대결**(수동 `COMMITTED` 또는 자동 첫 `RUN_PROGRESS`) ② **전적 초기화 성공** ③ **다른 페이지로 이동**(세션 폐기). **모드 전환(과 자동 설정 변경)만으로는 해제하지 않는다.** 닫기 버튼과 타이머는 두지 않으며 해제는 낭독하지 않는다(나타날 때 한 번만 낭독).

### "재시도 실패" 낭독 문구 ✅ (승인 2026-11-05)

`저장을 다시 시도했지만 실패했어요. 연습 대결은 계속할 수 있어요.` — `role="alert"`로 낭독하며 낭독 전용(시각적으로 숨김)이다. 알림 박스의 보이는 문구와 상태는 바뀌지 않고 "저장 다시 시도" 버튼이 다시 활성화된다.

## 6. 낭독 문장과 대표 live region (D1 승인: 단일 `role="status"` 모델)

**대표 live region**: 결과 영역(`region` "최근 라운드 결과") 안의 `role="status"` **1개**(v1처럼 화면에는 보이지 않음). 수동 대결 결과와 자동 실행·초기화·재시도·복구의 상태 낭독을 모두 이 한 곳이 담당한다. 요약 박스, 실행 중 안내, 진행 문구, 재시도·복구 박스는 **시각 표시일 뿐 live region이 아니다**. 예외는 오류를 즉시 알리는 `role="alert"`(저장 실패(수동), 읽기 실패, 초기화 실패, 기록 조회 오류, 재시도 실패)뿐이다.

변수: `{N}` = 선택한 전체 횟수, `{k}` = 확정·저장된 횟수, `{a}`·`{b}`·`{c}` = **이번 실행**에서 확정된 승·패·무 횟수(누적 전적이 아님).

### 승인된 자동 실행·초기화 문장 ✅ (2026-11-05)

| # | 문장 (원문) | 낭독 시점 |
|---|---|---|
| 1 | `자동 대결 {N}회를 시작했어요.` | 애니메이션 실행이 시작될 때 한 번 |
| 2 | `자동 대결 {N}회를 처리하고 저장하고 있어요.` | 즉시 결과 실행이 시작될 때 한 번 |
| 3 | `자동 대결을 중지했어요. {N}회 중 {k}회가 저장됐어요. 승 {a}회, 패 {b}회, 무 {c}회.` | 중지 요청 후 진행 중이던 묶음의 저장이 끝나 결과가 확정된 시점(클릭 순간이 아님). 애니메이션 전용 |
| 4 | `자동 대결 {N}회를 완료했어요. 승 {a}회, 패 {b}회, 무 {c}회.` | 마지막 묶음이 확정된 시점. 마지막 묶음 확정과 중지가 겹치면 완료로 처리. 즉시·애니메이션 공통 |
| 5 | `저장에 실패해 자동 대결이 중단됐어요. {k}회까지 저장됐어요.` | 실행 중 저장이 실패해 중단된 시점. 즉시·애니메이션 공통. 중지 요청과 겹쳐도 이 문장이 우선(G-8) |
| 6 | `누적 전적과 대결 기록을 모두 초기화했어요.` | 초기화가 성공한 뒤 |

### 낭독 책임표 (중복 낭독 방지)

| 사건 | 낭독하는 곳 (하나) | 표시만 하는 곳 |
|---|---|---|
| 수동 대결 결과(저장됨) | 대표 status — 수동 대결 문장 | 대결 영역(`aria-hidden`) |
| 수동 대결 결과(저장되지 않음) | 대표 status — 수동 대결 문장 + 꼬리표 | "저장되지 않음 · 연습 대결" 칩(`aria-hidden`) |
| 수동 저장 실패로 저장 불가 진입 | **`role="alert"`** 저장 안내(원인·조치) | — |
| 자동 대결 시작·처리 중·중지·완료·중단 | **대표 status** 1~5번 | 진행 표시줄(값은 `progressbar`가 읽힘), 실행 중 안내, 요약 박스, 저장 안내 박스(중단으로 진입한 경우 live 없음) |
| 읽기 실패(로드·기록 조회) | **`role="alert"`** | — |
| 초기화 진행 중 | 낭독 없음 | "초기화하는 중이에요…"(버튼 `aria-busy`) |
| 초기화 성공 / 실패 | 성공: **대표 status** 6번 / 실패: **`role="alert"`** | — |
| 재시도 중·복구됨 | **대표 status** (이전 승인 문장) | 안내 박스(live 없음) |
| 재시도 실패 | `role="alert"` — `저장을 다시 시도했지만 실패했어요. 연습 대결은 계속할 수 있어요.` ✅ | — |

### 우선순위와 규칙
1. **한 사건은 한 영역만 낭독한다.** 허용된 유일한 중복은 수동 저장 실패 시 결과 문장의 `(저장되지 않음 · 연습 대결)` 꼬리표다(AC2-068이 접근 가능한 결과 문장에 같은 사실을 포함하도록 요구). 이때 `alert`는 원인·조치를, 결과 문장은 승패 결과를 말해 내용이 겹치지 않는다.
2. **우선순위**: 같은 시점에 둘이 갱신되면 `role="alert"`(assertive)가 먼저 낭독되고 대표 status(polite)가 이어진다.
3. **자동 대결이 저장 실패로 중단되면** 대표 status 5번이 낭독을 맡고, 같은 사건으로 나타나는 저장 안내 박스는 `role="alert"` 없이 표시한다(이중 낭독 방지). 저장 불가 상태 진입과 "저장 다시 시도" 버튼은 박스에 있고 키보드 탐색으로 읽힌다.
4. 자동 대결 중에는 **대결마다 낭독하지 않는다**(P-7, AC2-053). 대표 status는 시작·중지·완료·중단 시점에만 바뀐다.
5. 시각 문구(요약 박스 등)와 낭독 문구는 문장이 같을 필요는 없지만 **의미와 수치(`{N}`, `{k}`, `{a}`, `{b}`, `{c}`)는 일치**해야 한다.
6. 같은 문장이 연달아 나오면(예: 같은 결과가 연속) 일부 스크린리더는 재낭독하지 않을 수 있다. v1과 같은 한계이며 M-06에서 확인한다.
7. 낭독 문장은 reducer가 아니라 `announce.ts`의 순수 함수가 상태 전이 시점에 만들어 `announcement`에 넣는다.

## 7. 키보드·포커스·비활성

- 모든 상호작용 요소는 네이티브 `button`/`a`라 Tab으로 도달하고 Enter/Space로 조작된다(AC2-051). 포커스 링은 3px 실선 `#4e80df`, 오프셋 2px(분리형 버튼 사이 간격보다 작게). 탭·모드 토글 같은 붙은 요소는 안쪽 오프셋.
- 비활성 버튼은 투명도로 구분하되 의미는 안내 문구로도 전달한다(실행 중 초기화 불가 안내 등).
- 터치 영역은 모든 버튼 44×44 CSS px 이상(AC2-052).

## 8. 반응형 계약

- 컨테이너(앱 루트) 폭 기준. **600px 이하**: 패딩 12px, 탐색은 제목 아래, 대결 영역 축소, 선택 버튼은 연한 채움, 기록은 카드 목록. **601px 이상**: 패딩 24px, 표.
- 320px~1280px 이상에서 가로 스크롤 없음(AC2-052). 카드 폭은 데스크톱 772px, 390px 화면에서 366px이 기준값이다(최종 HTML 측정).
- `prefers-reduced-motion: reduce`: 전환·스피너·스켈레톤 애니메이션 없음(R-16).
