## 이 Spec의 위치 (v1과의 관계)

- v1(`001-rps-game`)은 승인·구현된 기능이며 **이 작업에서 변경하지 않는다**. v2는 v1 위에 기능을 추가하는 별도 Feature다.
- 아래 "v1 호환성" 표에 v1 항목별로 **유지 / 확장 / 대체**를 명시한다. v1 FR-007(전적 저장 방식)과 FR-008(초기화 동작)의 대체·확장은 **사용자가 승인했다**(Constitution IX).

## 용어: 대결의 "확정"

이 Spec에서 대결이 **확정**되었다는 것은 결과 판정이 끝나고 **개별 기록이 IndexedDB에 저장 완료**된 상태를 말한다. 누적 전적, 전체 대결 횟수, 기록 수, 진행 횟수 표시는 **확정된 대결만** 반영한다. 저장에 실패한 대결은 확정되지 않았으며 기록·누적 전적 어디에도 포함되지 않는다. (판정과 저장의 순서, 트랜잭션, UI 반영 방식은 Plan에서 설계한다.)

## 용어: 저장되지 않은 대결 · 연습 대결 · 저장 불가 상태

- **저장되지 않은 대결**: 판정은 되었으나 저장이 확정되지 않은 대결. 저장이 실패한 대결과 연습 대결이 여기에 속한다. 기록·누적 전적·전체 대결 횟수 어디에도 포함되지 않는다.
- **저장 불가 상태**: 기록 저장이 실패했거나 저장된 전적을 읽지 못한 뒤, 사용자가 '저장 다시 시도'에 성공하기 전까지의 상태(P-14). 게임 전체는 차단되지 않는다.
- **연습 대결**: 저장 불가 상태에서 사용자가 진행하는 수동 대결. 결과는 화면에 표시할 수 있으나 저장되지 않으며, 저장된 마지막 대결 결과와 구분하여 '저장되지 않음'을 명확히 안내한다(P-12).

## 확정된 결정 (사용자와 협의 완료)

| 영역 | 확정 내용 |
|---|---|
| 모드 | 수동 대결 / 자동 대결을 토글로 전환한다 |
| 자동 대결 | 즉시 결과·애니메이션 두 방식. 사용자의 손은 고정(가위·바위·보) 또는 랜덤. 컴퓨터는 기존 균등 난수 로직. 판정은 기존 순수 게임 로직 재사용 |
| 중지 | 애니메이션 중 중지하면 **실제 완료·저장된 대결만** 전적에 반영 |
| 합산 | 수동·자동 대결의 전적은 모두 합산 |
| 통계 | 전체 대결 횟수, 승·패·무, 승률(= 승 ÷ 전체 대결). 승률 분모에 무승부 포함 |
| 기록 | 모든 개별 대결을 기록하고 조회 가능. 기록에는 사용자 선택·컴퓨터 선택·결과 포함. 전체 기록과 통계는 별도 페이지 1개에서 제공 |
| 성능 | 대량 기록을 조회해도 화면 성능을 유지(목표 수치는 P-8, 미확정) |
| 저장 | IndexedDB가 전적과 개별 기록의 **유일한 영속 저장소**. 서버·로그인·외부 DB 없음. 모든 전적은 저장된 개별 기록을 기준으로 계산 |
| 저장 실패 | 게임 전체를 차단하지 않는다. 저장되지 않는 **연습 대결** 가능(전적·기록 미반영, 안내 필수). 자동 대결 중 실패하면 중단하고 저장된 대결만 반영. 저장 다시 시도 경로 제공, 복구되면 기록되는 대결 재개 |
| 초기화 | 확인 후 누적 통계·전체 기록·마지막 결과를 함께 초기화 |
| UI | `docs/references/rps-lab-v2-ui.html`이 최종 시각 기준(샘플 데이터·미리보기 도구·상태 전환 방식은 요구사항 아님). Figma와 기존 `rps-lab-v2-final.html`은 참고 자료. v1 디자인·사용성 최대 유지. 게임 / 기록·통계 2개 영역 |
| 불변식 | `전체 대결 횟수 = 승 + 패 + 무 = 저장된 개별 기록 수` |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기록되는 수동 대결과 합산 전적 (Priority: P1)

사용자는 v1과 똑같이 직접 손을 골라 대결하고, 확정된 대결마다 개별 기록이 남으며 승·패·무 전적에 합산된다.

**Why this priority**: v2의 모든 통계와 기록의 바탕이다. 수동 대결이 기록되지 않으면 자동 대결·기록 페이지가 의미가 없다.

**Independent Test**: 수동 모드에서 몇 번 대결한 뒤 전적 합계와 기록 수가 일치하는지, 새로고침 후에도 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **AC2-001** — **Given** 게임 페이지를 처음 연다, **When** 화면을 본다, **Then** 수동 대결 모드가 선택되어 있고 v1과 같은 선택 버튼 3개·대결 결과 영역·누적 전적·전적 초기화 버튼이 같은 위치에 보인다. *(FR2-001, FR2-003, FR2-021)*
2. **AC2-002** — **Given** 모드 토글이 있다, **When** 사용자가 마우스나 키보드로 모드를 전환한다, **Then** 선택된 모드가 시각적으로 구분되고 보조기술에도 현재 선택 상태가 전달되며 다른 모드는 선택 해제로 표시된다. *(FR2-001)*
3. **AC2-003** — **Given** 수동 모드이다, **When** 사용자가 손을 하나 선택한다, **Then** v1과 동일하게 양쪽 선택과 결과가 표시된다(v1 AC-002, AC-003이 그대로 성립). *(FR2-002)*
4. **AC2-004** — **Given** 수동 모드이다, **When** 대결이 1회 확정된다, **Then** 개별 기록이 정확히 1건 추가되고 해당 결과의 승/패/무와 전체 대결 횟수가 각각 정확히 1 증가한다. *(FR2-002, FR2-012)*
5. **AC2-055** — **Given** 수동 모드이다, **When** 사용자가 서로 다른 입력을 빠르게 N회 연속 수행한다(v1 AC-022), **Then** 어떤 입력도 저장 지연 때문에 유실·중복되지 않고, 입력마다 정확히 1회의 대결이 처리되어 저장이 모두 성공하면 기록이 정확히 N건 추가된다. *(FR2-002, FR2-012, FR2-017)*

### User Story 2 - 자동 대결 즉시 결과 (Priority: P1)

사용자는 자동 모드에서 내 손 방식과 대결 횟수를 정하고 "즉시 결과"로 실행해 대량 대결의 결과를 한 번에 본다.

**Why this priority**: v2의 핵심 신규 기능이다. 즉시 결과만으로도 가치(확률·통계 실험)가 완결된다.

**Independent Test**: 자동 모드에서 내 손을 고정하고 즉시 결과로 N회 실행해 기록 수와 전적 증가량이 N인지 확인한다.

**Acceptance Scenarios**:

1. **AC2-005** — **Given** 수동 모드이다, **When** 화면을 본다, **Then** 자동 대결 설정·실행 UI는 표시되지 않는다. *(FR2-003)*
2. **AC2-006** — **Given** 자동 모드로 전환했다, **When** 화면을 본다, **Then** 자동 대결 설정·실행 UI가 표시되고 수동 선택 버튼은 표시되지 않으며(P-3), 대결 결과 영역·누적 전적·전적 초기화 버튼은 그대로 보인다. *(FR2-003)*
3. **AC2-007** — **Given** 자동 모드이다, **When** 내 손 방식을 본다, **Then** "고정"과 "매번 랜덤" 중 하나를 선택할 수 있고, 고정이면 가위·바위·보 중 하나를 고를 수 있으며 랜덤이면 손 선택 UI가 나타나지 않는다. *(FR2-004)*
4. **AC2-008** — **Given** 자동 모드이다, **When** 실행 방식을 본다, **Then** "즉시 결과"와 "애니메이션" 중 하나를 선택할 수 있다. *(FR2-004)*
5. **AC2-009** — **Given** 자동 모드이다, **When** 대결 횟수를 본다, **Then** 10회 / 100회 / 1,000회 중 하나를 선택할 수 있고 선택한 값이 표시된다(OQ-1). *(FR2-004)*
6. **AC2-010** — **Given** 내 손이 고정(예: 바위)이다, **When** N회 실행한다, **Then** 모든 대결에서 사용자의 손은 고정한 손이고, 내 손이 랜덤이면 충분히 많은 횟수에서 세 손이 모두 사용된다(난수는 주입하여 재현 가능하게 검증). *(FR2-004, FR2-005)*
7. **AC2-011** — **Given** 자동 대결이 진행된다, **When** 각 대결을 판정한다, **Then** v1의 판정 규칙(가위>보, 바위>가위, 보>바위, 같으면 무승부)과 9가지 조합 모두 일치하고, 컴퓨터의 선택은 v1과 같은 균등 확률(각 1/3)의 주입 가능한 난수로 결정된다. *(FR2-005)*
8. **AC2-012** — **Given** 즉시 결과로 N회를 선택했다, **When** "자동 대결 시작"을 누르고 모든 대결이 확정된다, **Then** 정확히 N건의 기록이 추가되고 승·패·무 합계가 정확히 N 증가하며, 완료 후 최종 전적과 마지막 대결 결과(나 | 결과 | 컴퓨터)가 표시된다. *(FR2-006)*
9. **AC2-013** — **Given** 즉시 결과가 완료되었다, **When** 화면을 본다, **Then** 시작 버튼이 다시 사용 가능하고 오류 없이 새 자동 대결 또는 수동 대결을 이어갈 수 있다. *(FR2-006)*
10. **AC2-062** — **Given** 즉시 결과로 자동 대결을 시작했다, **When** 대결을 처리·저장하는 동안이다, **Then** 진행 표시줄과 중지 버튼은 없지만 실행 중(저장 처리 중)임을 알리는 상태가 시각과 보조기술에 표시되고, 시작 버튼을 쓸 수 없어 같은 실행이 중복 시작되지 않으며(다른 조작도 AC2-018과 같이 제한), 완료 또는 저장 실패 시 상태가 해제된다(P-6). *(FR2-006, FR2-009)*

### User Story 3 - 애니메이션 자동 대결과 중지 (Priority: P2)

사용자는 자동 대결을 애니메이션으로 실행해 대결이 하나씩 진행되는 모습을 보고, 원할 때 중지한다. 중지 시 실제 완료·저장된 대결만 반영된다.

**Why this priority**: 사용자 경험을 높이는 방식이지만 즉시 결과가 먼저 성립해야 한다.

**Independent Test**: 애니메이션으로 실행 중 중지하여 기록 수·전적이 진행된 횟수와 정확히 같은지 확인한다.

**Acceptance Scenarios**:

1. **AC2-014** — **Given** 애니메이션 방식으로 N회를 시작했다, **When** 진행 중이다, **Then** 대결이 순서대로 대결 화면(나 | 결과 | 컴퓨터)에 표시되고 "진행 횟수 / 전체 횟수"와 진행 표시줄이 갱신된다. 기본 표시 간격은 약 70ms이며, 1,000회처럼 많은 횟수에서 일부 중간 결과의 화면 표시를 묶어 처리해도 진행 횟수 표시는 확정된 대결 수와 일치하고 기록·전적에는 모든 확정된 대결이 반영된다(OQ-1). *(FR2-007)*
2. **AC2-015** — **Given** 애니메이션이 끝까지 진행된다, **When** 완료된다, **Then** 정확히 N건의 기록이 추가되고 진행 표시와 중지 버튼이 사라지며 시작 버튼이 다시 사용 가능하다. *(FR2-007)*
3. **AC2-016** — **Given** 애니메이션이 진행 중이다, **When** 사용자가 중지한다, **Then** 더 이상 새 대결이 시작되지 않고 실제로 확정된 k건(0 ≤ k < N)만 기록·전적에 반영되며 나머지는 반영되지 않는다. 중지 요청 순간 저장 중이던 대결은 확정되면 포함, 그렇지 않으면 완전히 제외되며 어느 쪽이든 부분 반영은 없다. *(FR2-008)*
4. **AC2-017** — **Given** 중지했다, **When** 전적과 기록 수를 본다, **Then** 승 + 패 + 무 = 전체 대결 횟수 = 기록 수이고, 기록 증가분은 표시된 진행 횟수와 같으며, 화면의 마지막 대결 결과는 마지막으로 확정된 대결과 일치한다(P-12). 이후 새 자동 대결이나 수동 대결을 시작할 수 있다. *(FR2-008)*
5. **AC2-018** — **Given** 자동 대결이 실행 중이다, **When** 사용자가 모드 전환, 설정 변경, 새 자동 대결 시작, 수동 대결 중 하나를 시도한다, **Then** 해당 조작은 비활성화되거나 무시되어 진행 중인 실행과 기록에 영향을 주지 않는다. *(FR2-009)*
6. **AC2-019** — **Given** 자동 대결이 실행 중이다, **When** 사용자가 전적 초기화를 시도한다, **Then** 초기화는 수행되지 않는다(P-4: 먼저 중지해야 한다). *(FR2-009, FR2-019)*

### User Story 4 - 기록·통계 페이지 (Priority: P1)

사용자는 상단 탐색으로 "기록 · 통계" 페이지에 가서 전체 대결 횟수, 승·패·무, 승률과 모든 개별 대결 기록을 확인한다.

**Why this priority**: 요구사항에 명시된 핵심 결과물이며 저장된 기록의 확인 수단이다.

**Independent Test**: 수동·자동 대결을 섞어 진행한 뒤 기록·통계 페이지의 수치와 기록 목록이 게임 페이지의 전적과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **AC2-020** — **Given** 수동·자동 대결을 진행했다, **When** 게임 페이지의 누적 전적을 본다, **Then** 승·패·무는 수동·자동을 합산한 값이며 v1과 같은 위치에 최종 UI 레퍼런스의 스타일(승·패·무 색상 카드)로 표시된다. *(FR2-010)*
2. **AC2-021** — **Given** 수동·자동을 섞어 대결했다, **When** 전적과 기록 수를 본다, **Then** 승 + 패 + 무 = 전체 대결 횟수 = 저장된 기록 수이다. *(FR2-010, FR2-012)*
3. **AC2-022** — **Given** 기록·통계 페이지를 연다, **When** 통계 영역을 본다, **Then** 전체 대결 횟수, 승, 패, 무, 승률이 표시된다. *(FR2-011)*
4. **AC2-023** — **Given** 전적이 승 3 / 패 1 / 무 1이다, **When** 승률을 본다, **Then** 3 ÷ 5 × 100 = 60.0%이며 무승부는 분모에 포함된다. *(FR2-011)*
5. **AC2-024** — **Given** 기록이 0건이다, **When** 통계를 본다, **Then** 전체 대결 0회, 승률 0.0%(P-2)로 표시되고 0으로 나누는 오류가 없다. *(FR2-011)*
6. **AC2-025** — **Given** 대결이 1건 확정된다, **When** 기록을 본다, **Then** 수동·자동을 구분하지 않고 개별 기록 1건이 사용자 선택, 컴퓨터 선택, 결과(그리고 P-1에 따라 순번·일시)와 함께 존재한다. *(FR2-012)*
7. **AC2-026** — **Given** 저장된 기록이 있다, **When** 각 기록의 결과를 본다, **Then** 같은 기록의 사용자·컴퓨터 선택에 v1 판정 규칙을 적용한 결과와 항상 일치한다. *(FR2-012)*
8. **AC2-027** — **Given** 기록이 여러 건이다, **When** 기록 목록을 처음부터 끝까지 넘겨 본다, **Then** 모든 기록이 누락·중복 없이 조회된다. *(FR2-013)*
9. **AC2-028** — **Given** 기록이 21건 이상이다, **When** 기록 목록을 본다, **Then** 가장 최근에 확정된 대결이 먼저 오는 최신순으로 한 페이지에 20건씩 표시되고, 이전/다음으로 이동할 수 있으며, 첫 페이지에서는 이전이, 마지막 페이지에서는 다음이 사용할 수 없는 상태로 표시된다. 기록 전체를 한 번에 화면에 렌더링하지 않는다(OQ-5). *(FR2-013)*
10. **AC2-029** — **Given** 기록이 0건이거나 조회 중이거나 조회에 실패했다, **When** 기록 영역을 본다, **Then** 각 상태에 맞는 안내가 표시된다(빈 상태, 불러오는 중, 오류). *(FR2-013)*
11. **AC2-032** — **Given** 어느 페이지에 있다, **When** 상단 탐색을 본다, **Then** `게임`과 `기록 · 통계` 두 영역이 있고 현재 위치가 구분되며, 선택하면 해당 페이지로 이동한다. *(FR2-015)*
12. **AC2-033** — **Given** 기록·통계 페이지이다, **When** 화면을 본다, **Then** 승률, 승·패·무 통계, 전체 대결 기록이 모두 있다. *(FR2-015)*
13. **AC2-063** — **Given** 넓은 화면(데스크톱)에서 기록·통계 페이지를 연다, **When** 기록 목록을 본다, **Then** 표 형태로 표시된다(열 구성: P-1). *(FR2-013)*
14. **AC2-064** — **Given** 좁은 화면(모바일, 기준 폭은 UI Contract에서 확정)에서 기록·통계 페이지를 연다, **When** 기록 목록을 본다, **Then** 가로 스크롤 없이 카드형 목록으로 표시되고, 각 카드에는 표와 같은 정보(순번·일시(P-1)·나·컴퓨터·결과)가 모두 있으며, 정렬(최신순)·한 페이지 20건·이전/다음 동작은 표와 같다. 어떤 폭에서도 같은 기록이 같은 순서로 보인다. *(FR2-013, FR2-022)*
15. **AC2-065** — **Given** 기록이 1건 이상이다, **When** 통계 영역을 본다, **Then** 승/패/무 비율 막대의 각 구간이 실제 승/패/무 비율과 같고, 범례에 승·패·무 이름과 퍼센트 텍스트(P-2 표기)가 표시된다. 퍼센트 반올림 합이 100.0%가 아닐 수 있다. *(FR2-024)*
16. **AC2-066** — **Given** 기록이 0건이다, **When** 통계 영역을 본다, **Then** 막대는 빈 상태이고 범례는 0.0%이며 오류가 없다. *(FR2-024)*
17. **AC2-067** — **Given** 보조기술이나 색각 차이가 있는 사용자이다, **When** 통계를 이해한다, **Then** 숫자 정보(총 횟수·승·패·무·승률·범례 텍스트)만으로 모든 정보를 얻을 수 있고, 막대는 색에만 의존하지 않으며(범례에 이름 텍스트) 보조기술에 중복·모호한 값을 주지 않고(장식 처리 또는 숫자와 일치하는 대체 텍스트) 키보드 포커스 대상이 아니다. *(FR2-024)*

### User Story 5 - 전적 초기화 (Priority: P2)

사용자는 확인 절차를 거쳐 누적 통계, 전체 대결 기록, 마지막 대결 결과를 한꺼번에 지운다.

**Why this priority**: 요구사항에 명시된 동작이며 데이터 정합성의 시험대다.

**Independent Test**: 기록이 쌓인 상태에서 초기화를 확인하면 통계 0, 기록 0건, 마지막 결과 초기 화면이 되고 새로고침 후에도 유지되는지, 취소하면 아무것도 바뀌지 않는지 확인한다.

**Acceptance Scenarios**:

1. **AC2-041** — **Given** 기록이 쌓여 있다, **When** 초기화를 확인하여 완료한다, **Then** 누적 통계가 0/0/0(총 0회)이 되고 모든 개별 기록이 삭제되며 대결 결과 영역은 첫 대결 전의 중립 화면으로 돌아간다. *(FR2-019)*
2. **AC2-042** — **Given** 초기화를 완료했다, **When** 새로고침한다, **Then** 통계와 기록은 여전히 0이다. *(FR2-019)*
3. **AC2-043** — **Given** 초기화 중 저장소 오류가 발생한다, **When** 결과를 본다, **Then** 통계·기록·마지막 결과 중 일부만 지워진 상태가 되지 않고(전부 초기화되거나 전혀 변경되지 않음) 사용자에게 안내된다. *(FR2-019)*
4. **AC2-044** — **Given** 사용자가 전적 초기화를 누른다, **When** 삭제가 확정되기 전이다, **Then** "전체 전적과 모든 대결 기록이 삭제되며 되돌릴 수 없다"는 취지의 확인 절차가 제공되고, 확인하기 전에는 통계·기록·마지막 결과가 변경되지 않는다(OQ-6). *(FR2-019)*
5. **AC2-060** — **Given** 초기화 확인 절차가 표시되어 있다, **When** 사용자가 취소한다, **Then** 통계, 전체 기록, 마지막 결과 모두 변경되지 않는다. *(FR2-019)*
6. **AC2-061** — **Given** 초기화가 진행 중이다, **When** 사용자가 수동 대결이나 자동 대결 시작을 시도한다, **Then** 새 대결은 시작되지 않고(비활성 또는 무시), 초기화가 끝난 뒤에는 정상적으로 대결할 수 있다. *(FR2-019)*

### User Story 6 - 저장 실패·중단에도 일치하는 기록과 연습 대결 (Priority: P2)

새로고침, 중지, 페이지 이동, 저장 실패가 있어도 사용자가 보는 전적·통계와 저장된 기록은 서로 어긋나지 않는다. 저장이 안 되는 상황에서도 게임 전체가 막히지 않아 사용자는 저장되지 않는 연습 대결을 하고, 저장을 다시 시도해 복구할 수 있다.

**Why this priority**: 요구사항에 명시된 정합성 조건이다. 기능 신뢰성의 핵심이다.

**Independent Test**: 자동 대결 실행 중 새로고침·중지·이동·저장 실패를 일으킨 뒤 전적 합계와 기록 수를 비교하고, 저장 불가 상태에서 연습 대결·재시도·복구를 확인한다.

**Acceptance Scenarios**:

1. **AC2-034** — **Given** 기록과 전적이 있다, **When** 새로고침하거나 같은 브라우저로 다시 접속한다, **Then** 전적·통계·기록이 이전과 동일하다. *(FR2-016)*
2. **AC2-035** — **Given** 대결 결과가 표시되어 있다, **When** 새로고침한다, **Then** 마지막 대결 결과는 복원되지 않고 첫 대결 전의 중립 화면이 표시된다(v1과 동일). *(FR2-016)*
3. **AC2-036** — **Given** 수동·자동 실행, 중지, 새로고침을 임의의 순서로 수행했다, **When** 전적과 기록 수를 비교한다, **Then** 항상 승 + 패 + 무 = 전체 대결 횟수 = 저장된 기록 수이다. *(FR2-017)*
4. **AC2-037** — **Given** 대결 도중 중지, 새로고침, 저장 실패가 발생했다, **When** 기록을 본다, **Then** 각 대결은 기록 전체가 저장되었거나 전혀 저장되지 않았고, 일부 항목만 있는 기록이나 중복 기록이 없다. *(FR2-017)*
5. **AC2-038** — **Given** 자동 대결이 실행 중이다, **When** 새로고침한다, **Then** 자동 대결은 종료되고, 새로고침 전에 저장이 완료된 대결만 기록·전적에 남으며, 새로고침 후 자동으로 재개되지 않고(설정과 진행 상태는 복원되지 않는다) 이후에도 AC2-036이 성립한다(OQ-2). *(FR2-017)*
6. **AC2-059** — **Given** 자동 대결이 실행 중이다, **When** 사용자가 앱 안에서 다른 페이지로 이동한다, **Then** 자동 대결은 중지되고 중지 전에 완료·저장된 대결만 전적에 반영되며, 게임 페이지로 돌아와도 자동으로 재개되지 않는다(OQ-2). *(FR2-017)*
7. **AC2-039** — **Given** 기록 저장이 실패한다(용량 초과, 저장소 사용 불가 등), **When** 사용자가 대결한다, **Then** 저장 실패가 사용자에게 안내되고 오류로 화면이 중단되거나 깨지지 않으며 게임 화면은 계속 사용할 수 있다(저장 불가 상태, 연습 대결). *(FR2-018)*
8. **AC2-040** — **Given** 대결의 저장이 실패했거나 연습 대결을 했다, **When** 전적과 기록 페이지를 본다, **Then** 그 대결은 기록과 누적 전적(전체 대결 횟수 포함) 어디에도 포함되지 않으며, 화면의 전적은 항상 저장된 기록과 일치한다(임시 전적 없음, OQ-4). *(FR2-018)*
9. **AC2-056** — **Given** 저장 불가 상태이다, **When** 사용자가 수동 대결을 한다, **Then** 대결은 진행되고 결과가 표시되며(연습 대결), 저장되지 않는다는 안내가 화면에 계속 보이고 보조기술에도 전달되어 사용자가 기록되는 것으로 오해하지 않는다. 사용자가 명시적으로 '저장 다시 시도'에 성공하기 전에는 대결마다 자동으로 저장을 재시도하지 않으며 새 수동 대결은 모두 연습 대결로 처리된다(P-14). *(FR2-018)*
10. **AC2-057** — **Given** 자동 대결(즉시 결과·애니메이션 모두) 도중 저장이 실패한다, **When** 실패가 발생한다, **Then** 자동 대결은 중단되고 사용자에게 안내되며, 이미 저장된 대결만 기록·전적에 반영되고 실패한 대결은 포함되지 않는다. 이후 AC2-036이 성립하고 저장 불가 상태가 된다. *(FR2-018)*
11. **AC2-058** — **Given** 저장된 전적을 읽을 수 없다(저장소 오류·사용 불가), **When** 게임 페이지나 기록·통계 페이지를 연다, **Then** 전적이 실제 0인 것처럼 0/0/0으로 표시하지 않고 읽기 실패를 안내하며, 저장 불가 상태로서 연습 대결을 할 수 있다. *(FR2-018)*
12. **AC2-068** — **Given** 저장되지 않은 대결(저장 실패한 대결 또는 연습 대결)의 결과가 대결 화면에 표시된다, **When** 화면을 본다, **Then** 저장된 마지막 대결 결과와 시각적으로 구분되는 '저장되지 않음(연습)' 표시가 있고 접근 가능한 결과 문장에도 같은 사실이 포함되며, 표시된 결과는 누적 전적을 바꾸지 않는다(P-12). *(FR2-018)*
13. **AC2-069** — **Given** 저장 불가 상태이다, **When** 사용자가 키보드나 마우스로 '저장 다시 시도'를 실행한다, **Then** 시도 중임이 표시되고, 실패하면 저장 불가 상태와 안내가 유지되며 앱이 깨지지 않고, 성공하면 저장 불가 안내가 해제되고 복구되었음이 안내된다. *(FR2-025)*
14. **AC2-070** — **Given** 저장이 복구되었다, **When** 사용자가 이후 수동·자동 대결을 한다, **Then** 확정된 대결만 정상적으로 기록·전적에 반영되고(AC2-004, AC2-012 성립), 복구 전의 연습 대결과 실패한 대결은 소급 저장되지 않으며, 화면은 연습 결과를 저장된 마지막 결과로 오인되게 남기지 않고, AC2-036 불변식이 성립한다. *(FR2-025)*
15. **AC2-071** — **Given** 저장 불가 상태이다, **When** 사용자가 자동 대결을 시작하려 한다, **Then** 시작할 수 없고(비활성 또는 무시) 저장을 복구하면 가능하다는 취지가 안내된다(P-14). *(FR2-025)*

### User Story 7 - 저장된 기록만이 전적의 근거 (v1 전적 비이전) (Priority: P3)

v2의 전적은 IndexedDB에 저장된 개별 기록에서만 만들어진다. v1 localStorage 전적은 이전하지도, 사용하지도 않는다. (배포 이력이 없고 실사용자 데이터가 없으므로 이전 기능은 구현하지 않는다. OQ-3)

**Why this priority**: 불필요한 이전 기능을 만들지 않고, 전적과 기록이 항상 같은 근거에서 나오도록 보장한다.

**Independent Test**: v1 형식의 localStorage 값이 있는 브라우저에서 v2를 열어도 전적이 0/0/0으로 시작하고 그 값이 어디에도 반영되지 않는지, 대결 후 전적이 기록 수와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **AC2-045** — **Given** 브라우저에 v1 형식의 localStorage 전적이 있거나 없다, **When** v2를 처음 연다, **Then** 전적은 어느 경우든 0/0/0(총 0회)으로 시작하고 이전 절차나 안내가 표시되지 않는다. *(FR2-020)*
2. **AC2-046** — **Given** v1 형식의 localStorage 전적이 있다, **When** v2에서 대결·초기화·새로고침을 한다, **Then** 그 값은 읽히지도, 합산되지도, 수정·삭제되지도 않으며 전적은 항상 저장된 기록 수와 일치한다. *(FR2-020)*
3. **AC2-047** — **Given** localStorage의 v1 값이 손상되었거나 읽을 수 없다, **When** v2를 연다, **Then** 앱은 정상 동작하며 그 값이 오류의 원인이 되지 않는다. *(FR2-020)*

### Edge Cases

- **자동 대결 직전·직후**: 대결 횟수를 가장 작은(10회)/가장 큰(1,000회) 선택지로 실행, 완료 직후 즉시 재시작, 중지 직후 재시작.
- **중지 타이밍**: 마지막 대결이 확정되는 순간에 중지를 누르면 완료로 처리하고 이중 반영하지 않는다(AC2-015/016). 중지 순간 저장 중이던 대결은 확정되면 포함, 아니면 제외(AC2-016).
- **빠른 수동 입력과 저장 지연**: 저장 확정이 느려도 입력은 유실·중복되지 않고 입력마다 1회의 대결로 처리된다(AC2-055, v1 FR-006). 한 입력의 저장이 실패하면 그 대결만 제외한다(AC2-040).
- **같은 손 연속·랜덤 손**: 고정 손으로 같은 선택이 반복되어도 정상이며 컴퓨터 선택은 사용자 선택이나 이전 결과에 영향받지 않는다(v1 FR-002).
- **대량 기록**: 수만 건 이상에서도 조회·이동·통계 계산이 화면을 멈추지 않는다(AC2-030, 031).
- **저장소 사용 불가·용량 초과**: 시크릿/프라이버시 설정, 저장소 차단, 용량 부족 시 앱이 깨지거나 게임 전체가 막히지 않는다. 저장 불가 상태가 되어 사용자는 저장되지 않는 연습 대결을 할 수 있고, 연습 대결은 전적·기록에 반영되지 않으며 그 사실을 명확히 안내한다. 저장 다시 시도로 복구하면 기록되는 대결이 재개된다(AC2-039, 040, 056, 058, 068~071). *(v1과 달라지는 점: v1은 저장 불가여도 플레이와 화면 전적 표시가 가능했으나 v2는 저장되지 않은 대결을 전적에 반영하지 않는다)*
- **저장 불가 상태에서의 초기화**: 저장소를 쓸 수 없는 동안의 초기화는 확인 후 실패할 수 있으며, 그 경우 일부만 지워지지 않고 안내한다(AC2-043).
- **재시도 반복 실패**: 저장 다시 시도가 계속 실패해도 앱은 깨지지 않고 연습 대결은 계속할 수 있다(AC2-069).
- **다중 탭(P-9)**: 두 탭에서 동시에 대결해도 기록은 유실·중복되지 않는다. 다른 탭 화면의 실시간 반영은 보장하지 않으며 새로고침·페이지 진입 시 최신이 반영된다.
- **백그라운드 탭**: 브라우저가 타이머를 늦추면 애니메이션 진행이 느려질 수 있으나 기록 정합성은 유지된다.
- **초기화와 쓰기 경합**: 초기화 도중 새 기록이 끼어들어 일부만 남는 상태가 없어야 한다(AC2-043, 061). 자동 대결 실행 중에는 초기화하지 않는다(P-4).
- **기록 조회 중 변경**: 기록 페이지를 보는 동안 다른 탭에서 대결·초기화가 일어나도 화면이 깨지지 않는다. 최신 반영은 새로고침 시점이다.
- **일시 신뢰성**: 기기 시계가 바뀌어도 기록의 순서(최신순)는 확정 순서 기준으로 일관된다(OQ-5, P-1).
- **v1 localStorage 잔존값**: 개발 중 남은 값은 무시되며 어떤 영향도 주지 않는다(AC2-045~047).
- **JavaScript 비활성**: v1과 같이 지원하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

각 FR은 연결된 AC로 검증한다. 검증 방식은 Constitution VII에 따라 자동 테스트(Auto) 또는 명시적 수동 절차(Manual)로 구분하며 구체 절차는 Plan·Tasks에서 정한다.

**모드와 자동 대결**

- **FR2-001**: 게임 페이지는 수동 대결과 자동 대결을 전환하는 토글을 제공해야 한다. 첫 화면의 기본 모드는 수동이며, 현재 모드는 시각과 접근성 상태로 모두 구분되어야 한다. — AC2-001, AC2-002 (Auto + Manual)
- **FR2-002**: 수동 모드의 동작은 v1과 동일해야 하며(입력 1회 = 대결 1회, 컴퓨터 무작위 선택, 결과 표시, 빠른 연속 입력의 유실·중복 없음), 추가로 확정된 대결마다 개별 기록과 누적 전적에 반영되어야 한다. — AC2-003, AC2-004, AC2-055 (Auto)
- **FR2-003**: 자동 대결 설정·실행 UI는 자동 모드에서만 표시되어야 한다. 수동 모드에서는 자동 UI가 없고, 자동 모드에서는 수동 선택 버튼을 표시하지 않는다(P-3). 어느 모드에서도 대결 결과 영역·누적 전적·전적 초기화는 같은 위치에 유지한다. — AC2-001, AC2-005, AC2-006 (Auto)
- **FR2-004**: 자동 대결은 (a) 내 손 방식(고정: 가위·바위·보 중 하나 / 매번 랜덤), (b) 실행 방식(즉시 결과 / 애니메이션), (c) 대결 횟수(10 / 100 / 1,000회 중 하나)를 사용자가 설정할 수 있어야 한다. 랜덤 손은 세 손을 균등 확률로 고른다(P-5). — AC2-007, AC2-008, AC2-009, AC2-010 (Auto)
- **FR2-005**: 자동 대결의 컴퓨터 선택은 v1과 같은 균등 난수 선택 로직을, 승패 판정은 v1의 순수 게임 로직을 그대로 재사용해야 한다. 난수는 주입 가능해야 하고(Constitution VI) 판정 결과는 수동 대결과 동일해야 한다. — AC2-010, AC2-011 (Auto: 단위 테스트, 9조합 전수 + 분포)
- **FR2-006**: "즉시 결과"는 시작 후 설정한 횟수만큼 연속 실행하고 모든 대결이 확정되면 정확히 그 횟수의 기록과 전적을 반영하며 최종 전적과 마지막 대결 결과를 표시해야 한다. 실행 중에도 화면이 멈추거나 오류가 나지 않아야 한다. 진행 표시줄은 쓰지 않지만 저장 처리 중에는 실행 상태를 표시하고 같은 실행의 중복 시작을 막아야 한다(P-6). — AC2-012, AC2-013, AC2-062 (Auto)
- **FR2-007**: "애니메이션"은 대결을 순서대로 대결 화면에 표시하고(기본 간격 약 70ms) "진행 횟수 / 전체 횟수"와 진행 표시줄을 보여 줘야 한다. 1,000회도 과도하게 오래 걸리지 않아야 하며 처리 방식은 Plan에서 정한다. 끝까지 진행하면 정확히 설정한 횟수가 반영되고 누락·중복이 없다. — AC2-014, AC2-015 (Auto + Manual)
- **FR2-008**: 사용자는 애니메이션 실행 중 중지할 수 있어야 하며, 중지하면 **실제로 확정된 대결만** 기록과 전적에 반영하고 이후 상태가 일관되어야 한다. 즉시 결과에는 중지가 없다(P-6). — AC2-016, AC2-017 (Auto)
- **FR2-009**: 자동 대결 실행 중(즉시 결과의 저장 처리 중 포함)에는 모드 전환, 설정 변경, 새 자동 대결 시작, 수동 대결, 전적 초기화가 불가능해야 한다(비활성 또는 무시, P-4). 중지 또는 완료 후에 가능하다. — AC2-018, AC2-019, AC2-062 (Auto)

**전적·통계·기록**

- **FR2-010**: 수동·자동 대결의 확정된 결과는 하나의 누적 전적(승·패·무)에 합산되어야 하고 게임 페이지에서 v1과 같은 위치에, 최종 UI 레퍼런스(`docs/references/rps-lab-v2-ui.html`)의 스타일로 표시되어야 한다. — AC2-020, AC2-021 (Auto)
- **FR2-011**: 기록·통계 페이지는 전체 대결 횟수, 승, 패, 무, 승률을 제공해야 한다. 승률 = 승리 횟수 ÷ 전체 대결 횟수 × 100이며 무승부는 분모에 포함한다. 기록이 0건이면 0으로 나누는 오류 없이 0.0%로 표시한다(표기 형식: P-2). — AC2-022, AC2-023, AC2-024 (Auto: 단위 테스트)
- **FR2-012**: 확정된 모든 개별 대결(수동·자동 구분 없이)을 기록해야 한다. 기록에는 사용자 선택, 컴퓨터 선택, 승패 결과가 포함되며(순번과 일시: P-1), 결과는 두 선택과 v1 판정 규칙으로 항상 일치한다. — AC2-004, AC2-021, AC2-025, AC2-026, AC2-055 (Auto)
- **FR2-013**: 사용자는 기록·통계 페이지에서 저장된 모든 기록을 최신순(가장 최근에 확정된 대결이 먼저)으로, 한 페이지 20건씩, 이전/다음으로 조회할 수 있어야 한다. 기록 전체를 한 번에 화면에 렌더링하지 않으며, 빈 상태·불러오는 중·오류 상태를 안내해야 한다. 넓은 화면(데스크톱)에서는 표 형태를 유지하고 좁은 화면(모바일)에서는 가로 스크롤 대신 카드형 목록으로 같은 정보를 같은 순서로 표시한다. — AC2-027, AC2-028, AC2-029, AC2-063, AC2-064 (Auto + Manual)
- **FR2-014**: 대량의 기록이 있어도 기록·통계 페이지와 게임 페이지는 화면 성능을 유지해야 한다. 기록 전체를 한 번에 화면에 렌더링하지 않아야 한다(규모·목표·측정 방법: P-8, 미확정). — AC2-030, AC2-031 (Manual 측정)
- **FR2-015**: 상단 탐색은 `게임` / `기록 · 통계` 두 영역으로 구성하고 현재 위치를 구분해야 한다. 기록·통계 페이지는 승률, 승·패·무 통계, 전체 대결 기록을 포함한다. — AC2-032, AC2-033 (Auto)

**저장·정합성·초기화·비이전**

- **FR2-016**: IndexedDB에 저장된 기록과 그로부터 계산되는 누적 통계는 같은 브라우저에서 새로고침·재접속 후에도 유지되어야 한다. 마지막 대결 결과는 복원하지 않는다(v1과 동일). — AC2-034, AC2-035 (Auto)
- **FR2-017**: 화면의 전적과 통계는 저장된 기록과 항상 일치해야 한다(전체 대결 횟수 = 승 + 패 + 무 = 저장된 기록 수). 각 대결은 기록 전체가 저장되거나 전혀 저장되지 않아야 하며, 중지·새로고침·페이지 이동·저장 실패·빠른 연속 입력 상황에서도 기록이 유실·중복되지 않아야 한다. 자동 대결 중 새로고침하면 종료되고 저장 완료분만 유지하며, 앱 내 이동 시 중지되고, 어느 경우에도 자동 재개하지 않는다. — AC2-036, AC2-037, AC2-038, AC2-059, AC2-055 (Auto)
- **FR2-018**: 저장에 실패한 대결은 기록과 누적 전적에 포함하지 않으며(임시 전적 없음), 사용자에게 오류를 안내하고 앱이 중단되거나 깨지지 않아야 한다. 저장 실패는 게임 전체를 차단하지 않으며, 저장 불가 상태에서 사용자는 저장되지 않는 연습 대결(수동)을 할 수 있다. 연습 대결과 저장 실패한 대결은 전적·기록에 반영하지 않고 '저장되지 않음'을 명확히 안내하며, 결과는 화면에 표시할 수 있으나 저장된 마지막 대결 결과와 구분한다(P-12). 자동 대결 중 저장이 실패하면 자동 대결을 중단하고 이미 저장된 대결만 반영한다. 저장된 전적을 읽지 못할 때는 0/0/0으로 오인되게 표시하지 않고 안내한다. — AC2-039, AC2-040, AC2-056, AC2-057, AC2-058, AC2-068 (Auto)
- **FR2-019**: 전적 초기화는 사용자 확인 후에만 수행하며, 누적 통계, 전체 대결 기록, 마지막 대결 결과를 **함께** 초기화해야 하고 전부 성공하거나 전혀 변경되지 않아야 한다. 취소하면 어떤 데이터도 변경하지 않는다. 초기화 중에는 새 대결을 시작할 수 없다. — AC2-019, AC2-041, AC2-042, AC2-043, AC2-044, AC2-060, AC2-061 (Auto)
- **FR2-020**: v2는 IndexedDB를 전적과 개별 기록의 유일한 영속 저장소로 사용하고, 모든 전적을 저장된 개별 기록을 기준으로 계산해야 한다. v1의 localStorage 전적은 읽거나 이전·합산·삭제하지 않으며 레거시 전적 관리·마이그레이션 기능은 제공하지 않는다. — AC2-045, AC2-046, AC2-047 (Auto)

**호환·접근성·제약**

- **FR2-021**: v2는 v1의 수동 대결 동작과 UI 구조(대결 결과 영역, 결과 문장 1개, 누적 전적, 전적 초기화 버튼)를 유지해야 하며, v1 승인 문서는 이 작업으로 변경되지 않는다. 대체·확장되는 v1 항목은 "v1 호환성" 표에 명시한다. — AC2-001, AC2-048, AC2-049, AC2-050 (Auto + Manual)
- **FR2-022**: 모든 새 요소(토글, 자동 설정, 시작·중지, 진행 표시, 상단 탐색, 초기화 확인, 저장 다시 시도, 기록 표·카드 목록과 페이지 이동)는 키보드로 조작할 수 있고 접근 가능한 이름·상태를 가져야 하며, 320px~1280px 이상에서 페이지 가로 스크롤 없이 동작하고 모든 버튼의 터치 영역은 44×44 CSS px 이상이어야 한다. 자동 대결 중 결과는 대결마다 낭독하지 않고 시작·중지·완료 요약만 안내한다(P-7). — AC2-051, AC2-052, AC2-053, AC2-064 (Auto + Manual)
- **FR2-023**: 개별 기록은 브라우저 IndexedDB에 저장한다. 서버, 로그인, 외부 데이터베이스는 사용하지 않으며 개인정보를 수집하지 않고 게임·기록·통계 동작을 위한 네트워크 요청이 없어야 한다. — AC2-054 (Manual: Network 확인)

**통계 시각화·저장 복구**

- **FR2-024**: 기록·통계 페이지는 승·패·무 비율 막대 그래프와 퍼센트 범례를 포함해야 한다(P-10). 막대 구간의 비율은 실제 승/패/무 비율과 같고, 숫자 정보(총 횟수·승·패·무·승률·범례 텍스트)가 접근성의 기준이며 그래프는 색에만 의존하지 않고 보조기술에 중복·오해를 주지 않아야 한다. 기록 0건이면 빈 상태로 표시한다. — AC2-065, AC2-066, AC2-067 (Auto + Manual)
- **FR2-025**: 저장 불가 상태에서 사용자가 저장을 다시 시도할 수 있는 경로를 제공해야 하며, 사용자가 명시적으로 재시도에 성공하기 전까지는 연습 모드를 유지한다. 복구되면 안내하고 이후 대결은 정상적으로 기록하며, 복구 전의 연습·실패 대결은 소급 저장하지 않는다. 저장 불가 상태에서는 자동 대결을 시작할 수 없다(P-14). — AC2-069, AC2-070, AC2-071 (Auto)

| 결과 영역은 시각 표현만 있고(`aria-hidden`) 결과 문장(`role="status"`) 요소는 마크업에 없음. 보조기술 문장은 미리보기 패널에 텍스트로만 표시 | 결과 문장 1개(`role="status"`), 자동 대결 중에는 대결마다 낭독하지 않고 시작·중지·완료 요약만 안내(AC2-049, AC2-053, P-7) | 구현은 v1 UI Contract 구조와 Spec을 따른다. 단일 `role="status"` 낭독 모델은 사용자 승인됨(UI Contract 6절) |

다음 차이는 최종 UI 레퍼런스(`rps-lab-v2-ui.html`)에서 해결되어 제외했다: 실행 중 전적 초기화 허용·자동 중지(P-4), 실행 중 모드 토글 허용(FR2-009), 모바일 기록 표의 가로 스크롤(AC2-063·064), 저장 실패·읽기 실패·연습 대결·저장 다시 시도 UI(FR2-018·025), 즉시 결과의 실행 상태 표시(AC2-062), 승/패/무 색상 카드(P-11에 따른 항목별 승인: 게임·기록 두 페이지 모두 최종 UI 레퍼런스 스타일을 사용하기로 사용자 승인됨, UI Contract 9절). 이전 목업의 구현 방식(동기 반복 실행, 메모리 배열, `Math.random`, 1,000회 5건 묶음 표시)은 최종 UI 레퍼런스가 정적 목업이라 해당 없으며 구현 방식은 Plan에서 정한다.

**그 밖에 요구사항으로 해석하지 않은 UI 레퍼런스 요소**: 샘플 데이터(순번·일시·전적·기록 값), 시간 열 표기 형식, 미리보기 도구와 상태 전환 방식. UI 문구는 `rps-lab-v2-ui.html`의 문구를 사용자가 승인했으며 최종 문구는 UI Contract에 기록한다.

### Key Entities *(include if feature involves data)*

- **대결 기록(Battle Record)**: 확정된 하나의 대결 결과. 사용자 선택, 컴퓨터 선택, 승패 결과를 포함한다(P-1에 따라 순번·일시). 수동·자동을 구분하지 않는다. 한 번 저장되면 초기화 전까지 변하지 않는다.
- **누적 통계(Statistics)**: 저장된 대결 기록에서 도출되는 값. 전체 대결 횟수, 승, 패, 무, 승률. 항상 기록과 일치한다(`전체 = 승+패+무 = 기록 수`).
- **자동 대결 설정(Auto Run Settings)**: 내 손 방식(고정/랜덤)과 고정 손, 실행 방식(즉시/애니메이션), 대결 횟수(10/100/1,000).
- **자동 대결 실행(Auto Run)**: 설정에 따라 진행되는 한 번의 실행. 진행 횟수, 상태(진행 중/중지됨/완료/저장 실패로 중단)를 가진다. 기록에는 남지 않는 일시적 상태이며 새로고침 후 복원·재개하지 않는다.
- **저장 상태(Storage Status)**: 정상 / 저장 불가(저장 실패 또는 읽기 실패 후 복구 전). 저장 불가 상태에서는 연습 대결만 가능하고 자동 대결은 시작할 수 없다. 기록에는 남지 않는 일시적 상태이며 새로고침 후에는 저장소를 다시 확인해 정해진다.
- **연습 대결(Practice Battle)**: 저장 불가 상태에서 진행한 저장되지 않는 수동 대결. 기록·전적에 포함되지 않으며 복구 후에도 소급 저장하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

**성능과 반응 시간의 구체 수치(초 단위 목표, 기록 규모)는 확정하지 않았다.** 환경과 측정 방법을 먼저 정의하는 방안을 P-8에 제안했으며, 승인·측정 후 수치를 확정한다. 아래 SC 중 수치가 없는 것이 확정 기준이다.

- **SC2-001**: 자동 대결(즉시 결과) 100회와 1,000회를 시작한 뒤 결과가 화면에 표시되기까지의 시간을 P-8의 방법으로 측정하여 기록한다. 목표 수치는 측정 후 확정한다. (Manual/Auto)
- **SC2-002**: 모든 시나리오(수동, 자동, 중지, 새로고침, 페이지 이동, 저장 실패, 연습 대결, 저장 복구, 초기화)에서 승 + 패 + 무 = 전체 대결 횟수 = 저장된 기록 수의 불일치가 0건이다. (Auto)
- **SC2-003**: 기록 규모를 달리한 상태(P-8의 규모 단계)에서 기록·통계 페이지의 첫 화면 표시 시간과 페이지 이동 반응 시간을 P-8의 방법으로 측정하여 기록한다. 규모가 커져도 표시 시간이 기록 수에 비례해 늘어나지 않아야 한다. 목표 수치는 측정 후 확정한다. (Manual 측정)
- **SC2-004**: 애니메이션 중 중지 후 새 대결이 시작되지 않고 기록 수가 더 이상 증가하지 않는다(AC2-016). 중지 반응 시간은 P-8 방법으로 측정·기록한다. (Auto + Manual)
- **SC2-005**: 모든 기능이 키보드만으로 사용 가능하고 폭 320px~1280px 이상에서 페이지 가로 스크롤이 없다. (Manual/Auto)
- **SC2-006**: v1의 수동 대결 관련 인수 조건에서 회귀가 0건이다. (Auto)
- **SC2-007**: 자동 대결 1,000회가 실행되는 동안과 이후에 화면이 응답 없음 상태가 되지 않는다(측정: P-8). (Manual)

## 제안 항목 (P-1~P-14 모두 승인됨)

요구사항에 명시되지 않았으나 Spec을 테스트 가능하게 하려고 둔 **제안**이다. 사용자가 **P-1~P-13을 승인했다**(P-6·P-12는 보완 반영, P-8은 검증 방법만 승인하고 구체 수치는 실제 측정 전까지 미확정). P-14도 승인되어 **P-1~P-14 전체가 승인되었다.**

### P-1. 기록에 순번과 일시를 포함 — 승인됨
- **목적**: 목업의 `#`, `시간` 열 구현. 순번으로 "최신순"과 사용자가 보는 위치를 일관되게 표시
- **영향**: UX — 기록을 번호로 짚을 수 있다. 정합성 — 순번이 확정 순서이므로 기기 시계 변경에 영향받지 않는다. 일시는 표시용 정보일 뿐 순서 기준이 아니다
- **추천**: 승인(순번·일시 모두). 일시만 빼도 정합성에는 영향이 없다
- **미승인 시**: 기록 표에 번호·시간 열이 없어 목업과 달라진다. 순번이 없으면 AC2-025의 기록 구성이 선택·결과만으로 한정된다. (최신순 자체는 OQ-5로 확정되어 확정 순서를 기준으로 한다)

### P-2. 승률은 소수 첫째 자리까지, 기록 0건이면 `0.0%` — 승인됨
- **목적**: AC2-023·024를 테스트 가능하게 만드는 표기 규칙
- **영향**: UX — 표기 일관. 정합성 영향 없음(표시 규칙)
- **추천**: 승인
- **미승인 시**: 반올림·자릿수 기준이 없어 AC2-023(60.0%)과 0건 표시를 검증할 수 없고, 구현마다 표기가 달라질 수 있다

### P-3. 자동 모드에서는 수동 선택 버튼을 숨기고, 수동 모드에서는 자동 UI를 숨김 — 승인됨
- **목적**: 사용자 요구("자동 모드에서만 자동 UI")의 반대 방향까지 명확히 해 화면을 단순하게 유지
- **영향**: UX — 한 번에 하나의 조작 영역만 보여 혼동이 줄고 목업과 일치. 정합성 영향 없음
- **추천**: 승인
- **미승인 시**: 자동 모드에서 수동 버튼의 존재·동작이 불명확하다(자동 실행 중 수동 대결 금지 규칙과 충돌할 수 있다). AC2-006을 검증할 수 없다

### P-4. 자동 대결 실행 중에는 모드 전환·설정 변경·새 시작·수동 대결·전적 초기화 불가 — 승인됨
- **목적**: 실행 중 상태 변경으로 인한 경합 방지. OQ-6의 "초기화 중 새 대결 불가"와 짝을 이루는 반대 방향 규칙
- **영향**: UX — 초기화하려면 먼저 중지해야 한다(목업은 초기화 시 자동 중지). 정합성 — 실행 중 초기화와 저장이 겹쳐 기록이 일부만 남는 위험을 원천 차단
- **추천**: 승인
- **미승인 시**: 실행 중 초기화 처리 규칙(중지 후 초기화? 무시?)을 따로 정해야 하며 AC2-019·043·061의 경합 시나리오가 복잡해진다

### P-5. 사용자의 랜덤 손은 세 손을 균등 확률(각 1/3)로 선택 — 승인됨
- **목적**: "랜덤"의 의미를 컴퓨터 선택과 같은 기준으로 확정
- **영향**: UX — 예측 가능한 공정성. 정합성 영향 없음
- **추천**: 승인
- **미승인 시**: 랜덤 손의 분포가 정의되지 않아 AC2-010의 분포 검증 기준이 없다

### P-6. 즉시 결과에는 진행 표시줄·중지 버튼을 두지 않되, 저장 처리 중 실행 상태를 표시하고 중복 실행을 방지 — 승인됨(보완 반영)
- **정책**: 즉시 결과에는 애니메이션용 진행 표시줄과 중지 버튼이 없다. 저장 처리 중에는 '실행 중' 상태를 시각·보조기술로 표시하고, 시작 버튼 등을 막아 같은 실행의 중복 시작을 방지한다. 완료되거나 저장 실패하면 상태가 해제된다(AC2-062).
- **목적**: 사용자 요구가 "애니메이션 중 중지"이므로 즉시 결과는 단순하게 유지하되, 저장을 확정하는 동안 반응이 없어 보이거나 같은 실행이 여러 번 시작되는 것을 막는다.
- **영향**: UX — 단순하면서 처리 중임을 알 수 있다. 정합성 — 중복 실행으로 기록이 의도보다 많아지는 것을 방지한다.
- **메모**: P-8 측정에서 1,000회 즉시 결과가 길면 중지·진행 표시 추가를 재검토한다.

### P-7. 자동 대결 중에는 대결마다 낭독하지 않고 시작·중지·완료 요약만 안내 — 승인됨
- **목적**: 1,000회 실행에서 스크린리더 낭독이 폭주하는 것을 방지(v1 접근성 유지 요구)
- **영향**: UX — 보조기술 사용자의 사용성. 정합성 영향 없음
- **추천**: 승인
- **미승인 시**: 대결마다 낭독하면 1,000회에서 사실상 사용 불가, 요약만 안내하는 규칙이 없으면 AC2-053을 검증할 수 없다

### P-8. 성능 검증 방법 (수치는 확정하지 않음) — 방법 승인됨, 수치는 실제 측정 전까지 미확정
- **이전 안**: "기록 100,000건 기준 첫 화면 1초, 페이지 이동 0.5초, 즉시 결과 100회 1초, 중지 반응 0.5초"는 측정 환경·방법이 없는 후보 값이었으며 **확정하지 않았다**(SC2-001·003·004에서 수치 제거).
- **제안 검증 방법 (현실적인 안)**:
  1. **환경 정의**: 측정 기기·OS·브라우저 버전을 기록한다(기준 환경: 개발 PC의 최신 Chrome, 확장 프로그램 없음, 캐시 비움). 저사양 근사로 DevTools CPU 4배 스로틀 환경에서도 측정하고, 실제 모바일 기기 1대는 수동 확인한다.
  2. **데이터 규모 단계**: 1,000 / 10,000 / 100,000건. 측정용 시드 데이터는 개발용 도구로 IndexedDB에 만든다(제품 기능이 아님, 생성 방법은 Plan).
  3. **측정 지표**: ① 기록·통계 페이지 진입 → 통계와 첫 20건 표시까지 시간(`performance.mark/measure`), ② 이전/다음 클릭 → 갱신까지 시간, ③ 자동 1,000회 실행 중 50ms를 넘는 긴 작업 횟수와 최대 길이(응답성), ④ 중지 클릭 → 기록 증가가 멈출 때까지, ⑤ 자동 100/1,000회 완료까지 시간.
  4. **반복과 기록**: 각 지표를 5회 이상 측정해 중앙값과 최댓값을 검증 문서에 기록한다.
  5. **판정 기준 방식**: 절대값은 측정 후 사용자와 합의해 확정한다. 환경에 덜 민감한 **상대 기준**을 우선한다(예: 기록 100,000건일 때 첫 화면 시간이 1,000건일 때의 몇 배 이내 — 후보 2배, 미확정; 긴 작업 50ms 초과 0회 목표 등).
  6. **자동화 가능 범위**: 페이징·통계 계산 로직의 규모 독립성은 단위 테스트로 확인할 수 있다. 실제 IndexedDB 타이밍은 headless Chrome(CDP) 측정으로 하며, jsdom은 IndexedDB가 없어 fake 라이브러리가 필요하면 새 의존성이므로 Plan에서 Constitution II 정당화가 필요하다.
- **영향**: UX — 성능 약속의 근거가 생긴다. 정합성 영향 없음
- **추천**: 검증 **방법**은 승인, 수치는 측정 후 별도 확정
- **미승인 시**: FR2-014가 "화면 성능 유지"라는 주관적 표현에 머물러 검증 불가

### P-9. 다중 탭: 기록 유실·중복은 없어야 하나 다른 탭 화면의 실시간 반영은 보장하지 않음 — 승인됨
- **목적**: v1의 "탭 간 동기화 미보장" 가정의 연장. 범위를 단순하게 유지
- **영향**: UX — 두 탭을 열면 다른 탭의 최신 전적이 새로고침 전까지 보이지 않을 수 있다. 정합성 — 저장은 유실·중복 없이 유지
- **추천**: 승인
- **미승인 시**: 다중 탭 동작이 정의되지 않아 AC2-036 불변식이 두 탭에서 깨질 때 판단 기준이 없다. 실시간 동기화까지 요구하면 범위가 커진다

### P-10. 통계 페이지에 승·패·무 비율 막대 그래프와 퍼센트 범례 포함 — 승인됨(포함)
- **정책**: 목업의 통계 카드에 있는 한 줄 막대(승/패/무 비율만큼 3색 구간)와 `승 33.3% 패 33.3% 무 33.3%` 같은 범례를 포함한다(FR2-024, AC2-065~067). 라이브러리 없이 CSS로 만든다는 전제다.
- **접근성 기준**: 숫자 정보(총 횟수·승·패·무·승률·범례 텍스트)가 접근성의 기준이다. 그래프는 보조 시각 요소로 색에만 의존하지 않고(범례에 이름 텍스트), 보조기술에 중복·모호한 값을 주지 않는다(장식 처리 또는 숫자와 일치하는 대체 텍스트).
- **경계**: 기록 0건이면 빈 막대와 0.0%. 비율을 소수 첫째 자리로 표기하면 합이 100.0%가 아닐 수 있다(예: 33.3+33.3+33.3). 막대 구간 비율은 실제 비율을 따른다. 색상 의미는 P-11과 함께 UI Contract에서 정한다.
- **영향**: UX — 비율을 직관적으로 본다. 정합성 — 같은 통계에서 계산하므로 별도 데이터가 없다.

### P-11. 목업과 v1의 시각 차이는 UI Contract 단계에서 항목별 승인 — 승인됨
- **목적**: "v1 디자인 최대 유지"를 지키면서 최종 HTML의 새 시각 요소를 임의로 도입하지 않기 위한 절차
- **영향**: UX — 시각 변경이 사용자 승인을 거친다. 정합성 영향 없음. 승인 전에는 v1 스타일을 유지
- **추천**: 승인
- **미승인 시**: 목업과 v1 중 어느 쪽을 따를지 구현 단계에서 개발자가 판단하게 되어 계약이 흔들린다. 대상 후보: 승/패/무 색상 카드, 문구, '저장되지 않음' 표시의 모양, 카드형 목록의 세부 디자인(좁은 화면에서 카드형 목록으로 표시한다는 방향은 확정, AC2-064)

### P-12. 저장되지 않은 대결(저장 실패·연습)의 결과는 화면에 표시할 수 있으나 저장된 결과와 구분 — 승인됨(수정 반영)
- **정책**: 저장 실패한 대결과 연습 대결의 결과는 대결 화면에 표시할 수 있다. 단 저장된 마지막 대결 결과와 혼동되지 않도록 '저장되지 않음(연습)'을 시각적으로 구분하고, 접근 가능한 결과 문장(`role="status"`)에도 같은 사실을 포함한다. 표시된 결과는 누적 전적·기록을 바꾸지 않는다(AC2-068). 복구 후에는 연습 결과를 저장된 마지막 결과로 오인되게 남기지 않는다(AC2-070).
- **이전 안**: 실패한 대결을 마지막 결과 영역에도 표시하지 않음 → 사용자 정책으로 변경.
- **영향**: UX — 저장 실패 뒤에도 게임을 계속할 수 있고, 표시와 안내로 기록되는 것으로 오해하지 않는다. 정합성 — 화면에 보이는 결과가 전적을 바꾸지 않는다. 구분 표시의 문구·모양은 UI Contract에서 승인한다.

### P-13. 시스템의 "동작 줄이기" 설정이 켜진 경우의 애니메이션 처리 — 승인됨
- **배경**: 이전 안에 있던 접근성 추가 제안으로, OQ-1 결정에서 별도로 다뤄지지 않았다.
- **제안**: 동작 줄이기가 켜져 있으면 애니메이션 방식의 표시 간격을 줄이거나 움직임을 최소화한다(구체 방식은 UI Contract에서). 기록·전적 처리는 동일하다.
- **영향**: UX — 움직임에 민감한 사용자 보호. 정합성 영향 없음
- **추천**: 승인(작은 비용). 구체 동작은 UI Contract에서 확정
- **미승인 시**: v1 접근성 유지 요구와 충돌할 수 있는 움직임 처리가 정의되지 않은 채 남는다. 후속 개선으로 미뤄도 필수 요구사항에는 영향이 없다

### P-14. 저장 불가 상태의 운영 규칙 — 승인됨
- **승인**: (a), (b), (c) 모두 승인되었다. (b)는 사용자가 **명시적으로 "저장 다시 시도"를 실행해 성공하기 전까지** 연습 모드를 유지하는 것으로 확정되었다.
- **배경**: 최종 검토에서 연습 대결과 저장 재시도 경로가 정해졌으나 다음 세부 규칙은 명시되지 않아 제안한다.
- **제안**:
  - (a) 연습 대결은 **수동 대결로 한정**한다. 자동 대결(최대 1,000회)은 저장을 복구하기 전에는 시작할 수 없다(AC2-071).
  - (b) 저장 실패(또는 읽기 실패) 후에는 사용자가 '저장 다시 시도'에 성공하기 전까지 새 수동 대결을 모두 연습 대결로 처리한다. 대결마다 자동으로 저장을 재시도하지 않는다. 저장되는 대결과 연습 대결이 섞여 사용자가 혼동하는 것을 막기 위해서다.
  - (c) 복구 전의 연습·실패 대결은 복구 후에도 소급 저장하지 않는다(연습 대결은 기록에 반영하지 않는다는 정책의 연장).
- **목적**: 저장 상태에 대한 사용자 인식과 실제 저장 동작을 일치시키고 불변식을 지킨다.
- **영향**: UX — 상태가 명확하다. 대신 일시적 오류 뒤에도 사용자가 다시 시도를 눌러야 기록이 재개된다. 정합성 — 저장된 기록과 전적이 항상 일치한다.
- **미승인 시(참고)**: 연습 중 자동 저장 재시도 여부와 자동 대결 허용 여부가 미정이라 AC2-056, 069~071 일부를 확정할 수 없다. (a)를 거부하면 저장되지 않는 연습 자동 대결(최대 1,000회)의 의미를 따로 정의해야 한다.

## Assumptions (가정)

- 대상 사용자는 한 명이며 한 기기·한 브라우저에서 혼자 사용한다. 멀티플레이, 계정, 랭킹, 서버 동기화는 범위 밖이다.
- RPS Lab은 배포한 적이 없고 실제 사용자 데이터가 없다. 따라서 v1 localStorage 전적의 이전·정리 기능은 만들지 않는다(OQ-3).
- UI 문구는 한국어이며, 최종 UI 레퍼런스(`docs/references/rps-lab-v2-ui.html`)에 작성된 문구는 사용자 승인이 완료되었다. 구현 과정에서 새로 추가하거나 변경하는 문구는 v1 방식대로 UI Contract 단계에서 별도로 검토·승인받는다.
- 지원 환경은 v1과 같다(최신 Chrome·Safari·Firefox·Edge). IndexedDB를 쓸 수 없는 환경에서는 저장되지 않는 연습 대결만 가능하며 이를 안내한다(OQ-4 보완).
- 사운드, 사용자 정의 규칙(가위바위보 외), 기록 내보내기·가져오기, 기록 필터·검색, 다크 모드는 범위 밖이다.
- 기록은 대결 결과의 불변 사실이다. 개별 기록의 수정·부분 삭제는 제공하지 않고, 삭제는 전체 초기화로만 한다.
- 이 Spec은 구현 방법(저장소 접근 방식, 판정·저장 확정 순서, 전적 집계를 매번 계산할지 갱신 저장할지, 자동 대결 실행 방식, 상태 관리, 페이지 구성 방식)을 정하지 않는다. 어떤 방식이든 "전적은 저장된 기록과 항상 일치"(FR2-017)해야 한다. 상세 설계는 Plan 단계에서 한다.
- 성능 검증 방법(P-8)은 승인되었으나 구체 성능 수치는 실제 측정 전까지 확정하지 않는다. P-14를 포함해 P-1~P-14 전체가 승인되었다.
